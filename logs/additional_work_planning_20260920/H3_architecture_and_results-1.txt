    Architecture, sandbox evidence, and a larger-corpus experiment

                               CD / PC research working report

                                               Abstract

    Can a language predictor improve by inventing useful ways to read its context, while a neural
network learns how to combine their predictions? H3 explores this idea by placing a small nonlinear
predictive-coding cap above a frozen transformer and a bank of statistical readers. A structural
search constructs new context observers, fits next-byte distributions for them, and extends successful
observers with additional distinctions. At prediction time, the cap adjusts hidden activities and
reader reliability using errors on bytes that have already been observed.
    On Tiny Shakespeare, H3 improves over a matched H2-style fixed-reader linear cap in all five cap
initializations on both scored test segments. The clearer finding is that generated readers, including
a composed reader, add value beyond the same nonlinear cap with a fixed bank. Evidence for
nonlinear capacity and for predictive-coding training is more qualified: the linear generated-reader
cap remains strong, and larger fitting sets strengthen but do not settle the case for nonlinearity. We
give the implementation, equations, controls, numerical audits, failed objectives, costs and limitations,
then specify a restartable 6.5-hour Colab experiment on enwik8. The results support a concrete
architectural advance, not a general claim that predictive coding beats backpropagation or that the
complete CD program has been realized.



The strongest evidence concerns useful reader generation and composition. H3’s
nonlinear capacity is promising with more data; its general advantage and the
benefit of learned search guidance remain open.

1     What H3 is trying to accomplish

A conventional transformer learns a large collection of useful computations inside a fixed parameterized
architecture. The CD research program asks whether part of that computation can instead be made
explicit: propose a distinction between contexts, learn what that distinction predicts, reuse it in later
distinctions, and retain it if the resulting prediction improvement justifies its cost.
In this report, a reader is a procedure that takes the observed text prefix and returns a probability for
each possible next byte. One reader may trust a transformer, another may look up a recent suffix, and
another may use occurrences of the current partial word. The cap combines these distributions. It does
not need to relearn from scratch that a reader’s evidence points toward the byte ‘e’ rather than ‘x’.
H3 restores two mechanisms that were simplified in H2: genuine creation of new learned readers and a
nonlinear network of activities on which predictive coding can operate. It keeps H2’s useful probability
interface and causal evidence-based inference. The reader graph is discovered before final cap fitting
in the main experiment. A supplementary late-birth study tests growing an already trained cap, but
repeated ongoing structural learning is not part of the main H3 result.


1.1    Three distinct uses of learning

    1. Statistical memory: count which bytes follow each observed context class. This fits a reader’s
       distribution.
    2. Structural search: choose which context classes to create and which successful distinctions to
       refine. This learns the reader graph.
    3. Neural learning and state inference: learn how to combine readers, then adjust their reliability
       for a particular prefix using its recent evidence.

A good result in one of these roles does not establish superiority in the others. For example, a count
dictionary can greatly improve a small transformer without showing that PC training is better than BP.


1.2    The principal evidence, before the details

The primary experiment uses 16,384 cap-fitting targets and five cap seeds. H3 scores 2.316095 and
2.392021 bits per byte on the first and following test segments. A matched H2-style linear PC cap scores
2.332998 and 2.403120. H3 wins every seed on both segments.
Against a nonlinear PC cap with the fixed reader bank, the gains are 0.012176 and 0.013580 bpb, also
with five wins out of five on both segments. A reader formed by extending the first new reader contributes
beyond a cap trained with the first reader alone. These comparisons are the core architectural evidence.
At this fitting-set size, however, H3 beats a linear cap supplied with the same new readers on the first
segment and loses slightly on the following segment. A later exploratory study with 65,536 fitting targets
improves the nonlinear comparison. It is reported separately because it was motivated by inspection of
the primary test results.

2     From H1 through H2 to H3

2.1   What H1 did, and what “did not work” means

H1 already implemented a nonlinear PC-trained cap, structural growth, finite reader compositions,
historical proposal guidance and a compaction demonstration. Its added readers conveyed context
information through hashed categorical feature tables, followed by a neural residual writer over the
byte vocabulary. Its hidden layers had widths 32 and 32; its allocated cap contained 32,064 parameters,
including the feature tables and writer.
H1 was operational and its added features affected predictions. It nevertheless failed to establish a
competitive advantage over a simpler fixed cap. On its original test segment, calibrated fixed BP
scored 2.874994 bpb and CD-PC scored 2.877332, with fixed BP better in all three seeds. The frozen
transformer scored 2.896241. Thus H1 improved the base but did not justify its additional structural/PC
machinery on that comparison. Its final CD-PC graphs selected primitive copy readers rather than
useful composed towers. Historical guidance was essentially neutral.
H1’s deployment computation also offered little distinct evidence for PC to reconcile: its free prediction
was essentially a forward computation. The PC procedure supplied a form of training credit, rather
than adding substantial new observations during inference.


2.2   What H2 established

H2 changed the evidence interface. Thirteen readers emitted full next-byte distributions: the transformer,
eight smoothed suffix readers, three copy readers, and one copy reader with a suffix fallback. A small
gate learned their reliability and adjusted it using their performance on the last 16 observed bytes.
This was a much stronger predictor. The original H2 all-reader PC result was 2.332323 bpb on the first
segment; its five-reader compression-first version scored 2.335741. Compression-first selection beat an
update-matched fixed-five control, but the full bank remained slightly better. H2 therefore demonstrated
useful restricted structural selection, with a small predictive cost for fewer active readouts.
The large change from H1 is not an isolated interface ablation. H2 also introduced substantial count
memory fitted on 700,000 training bytes. It is reasonable to infer that preserving predictive evidence
helped, but the entire H1-to-H2 improvement cannot be assigned to that one change.

Think of the cap as a small committee chair. Each reader hands it an explicit probability distribution.
The chair first uses the current context to form an opinion about whose advice to trust. It then checks
how the readers explained the recent observed text and adjusts its internal state. The adjusted reliability
weights combine the next-byte predictions.
For an illustrative prefix such as the c, a partial-word reader groups it with other contexts whose
current partial word is c. A refined reader additionally observes that the preceding word is the. Its
next-byte counts may differ from contexts such as I c. The neural cap can learn when this lexical
evidence is useful relative to suffix or copy evidence. This example explains the mechanism; it is not a
claim about measured probabilities for that phrase.


3.1   How this fits the generalized-transformer view

At an abstract level, all three versions instantiate a repeated process of reading context, constructing
proposals, reconciling evidence, and writing a predictive state. In H3, a reader supplies a point in the
probability simplex

The cap writes a point in the convex hull of those reader distributions. Its Euclidean activity coordinates

Structural growth adds a new available point-valued function to this geometry.
This is a concrete special case of the broader generalized-transformer proposal, not a claim that

4     Generated readers as finite distinctions

4.1    Observers and refinement

Let c = x<t denote an observed context. An observer program ϕ assigns a discrete key ϕ(c). It induces
an equivalence relation
                                   c ∼ϕ c′ ⇐⇒ ϕ(c) = ϕ(c′ ).
Adding another observer ψ forms ϕ′ = (ϕ, ψ), which refines this partition: contexts formerly grouped
together can now be distinguished. This gives an executable finite interpretation of a distinction and its
composition.
The implemented grammar has 16 atoms: literal bytes at lags 1–12; the current partial word; the
preceding whitespace-delimited word; current partial-word length capped at 12; and the class of the
last byte (whitespace, uppercase, lowercase, digit or other). Words retain at most their last 12 bytes
and are observed within a 64-byte causal window. The word vocabulary is fitted and frozen on the
count-training prefix. Unknown words map to a reserved ID.
Programs select one to three atoms. Each atom ID fits in 21 bits and the tuple is packed into an
unsigned 64-bit key, avoiding hash collisions within these bounds. The initial pool contains the 16 atoms
plus three lag combinations. After a program is accepted, candidates can append another atom to it. A
parent pointer supplies a probabilistic backoff graph as well as a reusable program construction path.
Scope. Word segmentation and the atomic grammar are supplied by the implementation; search does
not discover them from nothing. This is a bounded observer/refinement system, not a full STLM or an
exact distinction-calculus quotient engine. A word-prefix child augmented with previous word formally
refines its parent partition. The suffix-6 fallback of the first reader is a probabilistic fallback, not evidence
that word-prefix observation refines the suffix-6 partition.

whereas BP differentiates the exact finite computation; these are not identically the same gradient.

6     Sandbox protocol and audit trail

6.1    Data, base and selection

All sandbox studies use the same 1,115,394-byte Tiny Shakespeare file with a contiguous 90/5/5 split.
H3 inherits a frozen byte transformer with two blocks, width 64, four heads and context length 64. It
has 120,576 distinct parameters; an earlier H1 count of 136,960 double-counted a tied matrix and is
corrected here.
Reader counts use the first 700,000 training bytes. Cap fitting uses 16,384 later training targets; the
outcome set contains 4,096 disjoint later targets. The first validation half supplies 4,096 development
targets and the second supplies 4,096 checkpoint-selection targets. Final scoring uses the first 32,768
targets after the test context offset, followed by the remaining 22,938 targets. The transformer had
already used the broader training region and validation in earlier work.
Six development fits compared learning rates 0.001 and 0.003 for fixed nonlinear PC, generated nonlinear
PC and generated BP at seed 101. Their mean development scores were 2.377239 and 2.373021
respectively, selecting 0.003. The final study used seeds 7, 19, 37, 53 and 71, eight arms per seed, 480
optimizer updates per fit, and selection checks every 40 updates. Checkpoint hashes were locked before
scoring the primary final models.


6.2    What the controls isolate

    • H2-style linear PC: refitted all-13-reader baseline under the H3 schedule and centered-PC
      implementation, not the historical H2 672-update number.
    • Fixed nonlinear PC: same nonlinear architecture without generated readers.
    • Generated linear PC: supplies the new readers to a strong low-capacity cap.
    • Generated BP: same nonlinear structure and free inference, different training credit.
    • First-reader-only PC: retrains with the first accepted program but omits its child.
    • Retrained no-inference cap: fits without prefix-evidence settling; stronger than a frozen
      switch-off diagnostic.
    • Random additions: same number of additional readouts and the same table-fitting rules, but
      different programs. This is not perfectly table-memory matched, and it can reference an accepted
      parent; it is not an independent random-search trajectory.

The five seeds vary cap fitting, not the base, corpus, dictionary or discovered graph. Both the corpus
and original test region have been used repeatedly during exploratory research. The following segment
adds within-corpus evidence, not an independent domain.

8.3    Prediction-time settling

For the trained H3 model, switching settling off increases loss by 0.003085 bpb on the first segment
and 0.001823 on the following segment. Replacing the correct prefix evidence with another context’s
evidence increases loss by 0.002308 and 0.000739 respectively. These frozen-model interventions show
that the deployed state inference uses local evidence.
The separately retrained no-inference model is closer: H3 gains 0.001614 and 0.000765 bpb, with four of
five and two of five seed wins. The second interval crosses zero. This distinction matters: an intervention
can show dependence on a component without proving that retraining a simpler system cannot recover
most of the benefit.

10     Late reader births and why refitting can matter

The staged scalar screen is cheap, but it can reject a reader whose value depends on learning when
to trust it. A development-only experiment exposed this limitation. Starting from an already fitted
fixed-reader nonlinear PC cap, every one of the 19 root proposals failed scalar insertion; the best outcome
gain was −0.000038 bpb and the word-prefix proposal scored −0.000793.
The cap was then actually enlarged and refitted for 160 updates at learning rate 0.001, alongside an
equally continued no-birth control. All branches restarted AdamW. New input/output connections
started at zero and the new reader bias at −4, making the initial function approximately, rather than
exactly, preserved.

11     Historical guidance and dependency towers

H3 supports dependency towers in a narrow, operational sense: accepted reader programs can serve
as parents of new programs, and their predicted distributions supply backoff values. The accepted
word-prefix/previous-word reader demonstrates one such extension.
The historical search guide is much less established. The H3 audit fits a ridge regressor using previous-
round labels and four candidate descriptors: fitting gain, support fraction, tuple length and estimated
code cost. It predicts outcome gain for the next round. With 19 earlier labels, the best gain in four
guide-nominated candidates tied the residual-only ranking at 0.002001. With 52 earlier labels, the
guide’s best was 0.000087, below the residual-only 0.000143.
This guide did not choose the deployed graph. There were only three closely related search states, too
little diversity to support a strong learning-to-search claim. H1 collected more trial labels, but still too
few independent states and trajectories to demonstrate a reliable guide advantage.
A meaningful next guide study should label contextually refitted candidate gains relative to equally
trained no-growth controls; vary data regions, cap states and perhaps corpora; then evaluate candidate
ranking on held-out search trajectories. Candidate count alone is not the effective sample size when
many labels share nearly the same state. The supplied larger notebook retains an audit-only guide and
saves all labels; it does not rely on unproven guide ranking to cut search.

12.2    Memory and time accounting

The inherited dictionary stores 89,746 contexts and 388,416 nonzero next-byte entries, serialized in
23,042,029 bytes (about 22 MiB). The two generated readers add 23,306 keys and 83,287 nonzero counts,
plus a shared vocabulary of 42,958 entries. The added reader/vocabulary deployment pickle is 1,574,180
bytes; added count arrays are 1,039,200 bytes. The 2,740,505-bit description proxy is much smaller
because it excludes the vocabulary and runtime representation. These quantities are not interchangeable.
Mean primary CPU fit times were approximately 12.3 seconds for the H2-style linear cap, 33.1 for fixed
nonlinear PC, 33.1 for H3 PC, 31.5 for generated BP and 15.3 for generated linear PC. They exclude
shared base/cache work, dictionary construction, structural search and final evaluation; ancillary jobs
sometimes overlapped. They support no end-to-end speed or hardware-efficiency claim.


12.3    What has not been established

  • No independent-corpus generalization result is yet available for H3.
  • No catastrophic-forgetting or continual-task-stream test is included in these H3 studies. Keeping
    reader tables does not freeze a neural routing function or guarantee retention.
  • No decentralized training, frontier-scale throughput or large-model co-distillation is demonstrated.
  • The observer grammar is bounded and hand-specified. Exact CD quotients, complete STLM
    search and a full RBII compression theorem are not implemented by these count tables.
  • The final prediction stays inside a reader mixture. The cap does not write an arbitrary new byte
    distribution outside that convex hull.
  • The main search is staged. Repeated neural/structural alternation remains a proposed experiment.

13     Why H3 is more successful than H1: evidence and interpretation

A careful answer has two levels.
Supported by matched H3 controls: generated readers improve the fixed-reader nonlinear cap; the
child improves over its parent alone; selected programs beat the random-addition control; causal settling
affects predictions; and a larger fitting set makes the nonlinear-versus-linear comparison more favorable.
These are directly tested relationships within H3’s setup.
Plausible explanation of the cross-version change: H3’s readers supply explicit predictive evidence,
its new programs fit meaningful conditional distributions, and the cap can learn context-dependent trust
before reconciling that trust with recent observed outcomes. H1 asked a comparatively small residual
network to turn hashed feature identities into corrections, while offering less additional evidence at
inference. The new interface and memory therefore reduce a plausible representation and estimation
burden.
Several changes are confounded across versions: dictionary size and training statistics, feature represen-
tation, cap design, objectives, search grammar, fitting schedules and inference. There is no one-factor
H1-to-H3 experiment that proves a unique cause. In particular, H2 already achieved most of the large
gain over H1 with a linear gate. H3’s further contribution is the more convincing demonstration of
reader creation and composition, plus a nonlinear route that becomes more competitive with more data.
It would be premature to say that the nonlinear PC mechanism alone explains H3’s success. The
same-reader BP model is close, and the same-reader linear PC model is strong. The more defensible
statement is that H3 makes the desired mechanisms useful enough to warrant a larger, better-controlled
test.

14.2      Data roles and evaluation

The first 90 MB train the base. The first 4 MB also fit fixed and generated reader counts; gate-fitting
blocks occur after that prefix. The next 5 MB are divided into base-selection and cap-selection halves.
The final 5 MB are held out, with 262,144 targets sampled in nonoverlapping contexts spread across
that region. Cap selection uses 16,384 targets. Search screens 16,384 fitting targets and 8,192 outcome
targets; final cap fitting uses the full 262,144-target fitting set.
These are selected-block bpb scores, not full-stream enwik8 leaderboard scores. All arms are paired on
the same positions. Test outcomes are evaluated after final model choices are locked, or after a clearly
marked partial-model lock if the budget runs out. No test outcome changes the training recipe.
The base-training allowance is at most 2.25 hours. The remaining active-time budget covers dictionary and
observer construction, proposal search, feature caching, cap training and evaluation. Once preprocessing
is complete, measured update/evaluation times select one common cap-update budget, reserving 30
minutes for final work. Equal update counts do not mean equal floating-point work or elapsed time.

14.3    Persistence and progress

The notebook stores corpus bytes, code, splits, observer vocabulary and matrix, every candidate, accepted
reader tables, cache shards, optimizer states, selected models, per-target losses and result summaries
in the selected Google Drive folder. It retains earlier checkpoint versions and performs no automatic
cleanup.
A payload is copied, hashed and verified before a separate immutable commit record is published. On
resume, incomplete writes are ignored and a corrupt newest committed payload falls back to an older
valid one. Base checkpoints occur approximately every five minutes, cap checkpoints approximately
every two minutes, with saves at completed stages and each candidate/cache shard. Training reports
progress about every 30 seconds.
The default limit is 6.5 recorded active hours across sessions, with at most seven allowed. Disconnected
time is excluded. A hard reset can lose the short unlogged interval, and a network stall or individual
save can outlast a timing check. This is a safe-boundary budget, not a guaranteed external wall-clock
limit. Colab resources and runtime availability vary [6].


14.4    What was tested before delivery

The delivered implementation passes 18 numerical, causal, persistence and integration tests. They
cover the inherited readers, nonlinear local gradients and weak-nudge behavior, empty-reader backoff,
actual child proposal creation, source/configuration locks, exact PC/BP optimizer continuation, and
target/future edits that leave current prediction inputs unchanged.
Every actual notebook code cell was executed in order in two fresh CPU processes using a local persistence
directory and a reduced 500,000-byte Tiny Shakespeare input. The first run completed seven conditions

15     Assessment and next decisions

The most useful next observation is whether generated readers improve a strong fixed-reader nonlinear
cap on a new corpus, while a generated-reader linear cap and same-architecture BP remain competitive
controls. A positive result on these comparisons would support reader generation as a scalable module
and clarify whether nonlinear activity inference adds value beyond the memory interface.
If scalar search accepts no useful candidates, the recorded trials can distinguish sparse support, size
ceilings and weak insertion gains. The development late-birth result suggests contextual refitting as
the next search objective to test; it does not justify silently replacing a failed screen with hand-selected
Shakespeare readers.
If H3 beats the fixed bank but not generated linear PC, the reader-generation idea can still be useful
while the nonlinear cap requires more evidence. If BP matches or beats PC, the reader architecture
remains viable and PC-specific claims should narrow accordingly. If all learned caps merely track the
global mixture, the new memory interface is doing most of the work.
H3 is therefore a meaningful step from operational components to useful structural contributions. The
remaining questions concern how much nonlinear state inference earns, how search should evaluate
conditional utility, how many independent search states a historical guide needs, and whether those
benefits persist when the base, data and costs are scaled together.
