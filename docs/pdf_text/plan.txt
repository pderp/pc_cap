A One-Month Programme for Continual-Learning Predictive-Coding
                           Caps
                on GPT-2-Scale Transformers
   Revised plan with controlled experiments and an executable implementation contract
                                    (readable edition)

                                   Ben Goertzel and Claude Fable

                  7 September 2026 – revised edition, rewritten for readability


                                                 Abstract
         This document plans one month of work on continual-learning “caps”: small learning systems
     attached to a frozen GPT-2-scale transformer that read its internal states and write corrections
     back into it. The primary question is whether routing a learning signal to the place where a small
     intervention measurably improves the current prediction reduces damage to unrelated knowledge,
     while still allowing useful transfer through shared mechanisms, at comparable acquisition, memory,
     and compute. The cap is built first on the ordinary backpropagation-trained (BP) model. A
     separate controlled comparison then isolates three things that are easy to confuse: the effect of
     an error-based predictive-coding (ePC) representation of the base, the effect of “settled” error
     credit as opposed to gradient credit, and the effect of retrieval features derived from errors. The
     cap of this month (“v0”) is a PC-motivated gated activation memory; it does not yet contain
     its own predictive-coding inference process, and the document is careful not to claim otherwise.
     Three test beds are used: a constructed modular fixture in which the right routing is known by
     construction, a learned synthetic grammar with shared and private latent causes, and lifelong
     editing of complete answers on zsRE and CounterFact. A bounded development phase precedes a
     frozen confirmatory protocol. Directly measured update-order effects are the main interference
     diagnostic; Hessian commutators are an optional, explicitly local diagnostic. Re-distillation of the
     ePC base is conditional on finding a specific deficit, and never forces unrelated domains to be
     orthogonal. The appendices specify execution, metrics, memory updates, resource accounting, and
     reporting, including how to finish an experiment whose answer is negative.

How to read this document
The document has two halves. The main body (Sections 1–12) explains what we are trying to find
out, why the experiment is shaped the way it is, and what each result would and would not mean. It
is written to be read from start to finish, and each technical idea is explained where it first appears.
The appendix is a contract for the coding agents who will run the programme: it fixes numbers,
procedures, and reporting formats. It is written to be looked up rather than read through, but every
rule in it is accompanied by a short reason, so that an agent (or a person) who meets a rule out of
context can see what it protects.
    A recurring theme is the distinction between a controlled contrast and a bundled comparison. If
two systems differ in three ways and one wins, we have learned that the bundle of three changes
helps, not which change helped. Most of the structure of this plan exists to make sure that every
comparison we draw conclusions from differs in exactly one thing.
    The glossary below collects the terms and symbols used throughout. Readers who already know
the area can skip it and return when needed.

Glossary and notation
Base
    The frozen pretrained transformer. BASE-BP is the ordinary backpropagation-trained model;
     BASE-EPC is its conversion into an error-based predictive-coding network. D is the number of
     layers, d the width of the residual stream.
Residual stream
                   (l)
    The vector ht carried through the network at layer l and token position t; each transformer
     block adds its output to it.
Cap
    The small learning system attached to the base. It reads residual-stream vectors and writes
     additive corrections back into them. Base weights never change.
Bank
     One module of the cap, attached at one depth. There are three banks, at roughly one third, two
     thirds, and the full depth of the base.
Slot
     One entry in a bank’s memory: a key (what to match against), a value (the correction to add), a
     radius (how close a query must be to fire the slot), and bounded metadata.
Key, query
    The key is the stored retrieval feature of a slot; the query is the feature computed from the
     current input. A slot fires if the query is within the slot’s radius of its key.
Credit, credit direction
    The signal that tells a bank which way to change a value so as to reduce the current loss. Two
     kinds are used: the adjoint and the settled error.
Adjoint
    The gradient of the loss with respect to a hidden vector, obtained by reverse-mode automatic
     differentiation (backpropagation through the frozen base).
Settled error
     In the ePC base, the error variable at a site after a fixed number of iterations of error inference
     conditioned on the target.

Delivery rule, highway
    The rule deciding which banks receive credit for an item. The arms C0, C1, C2, CR, CO are
    delivery rules. “Highway” is the informal name for delivering credit to a bank far from the
    output.
Router
    The component of C2 that chooses a bank by measuring where a small trial write improves the
    loss.
Arm
    One complete configuration (base, delivery rule, key type, memory protocol) run on a stream.
Contrast
    Two arms that differ in exactly one respect, so that a difference in results can be attributed to
    that respect.
Stream, realization, order
    A stream is the ordered sequence of items to be learned. A realization is one sampled set of
    items; an order (permutation) is one ordering of that set. We use three realizations and five
    orders each.
Acquisition
    Whether an item is learned at the time it is presented.
Retention
    Whether an item is still known at the end of the stream.
Locality
    Whether inputs unrelated to any learned item still receive the base’s answer.
Transfer
    Whether learning one item helps (positive) or harms (negative) performance on others.

    Development data may be used to tune and debug. Confirmation data are frozen in advance and

    accelerator time.


1    Purpose and summary
The aim is to come out of the month with research results that are interesting to people outside our
own group and that survive scrutiny. The object of study is a cap. A cap reads a frozen transformer’s
internal states and writes corrections into its residual stream. Its job is to acquire new facts and tasks
from a stream, retain the valid earlier ones, generalize to rephrasings, and leave unrelated behaviour
intact. Freezing the base’s weights preserves the original model as a recoverable reference; note that
it does not by itself preserve the behaviour of the model when the cap is switched on, since the cap’s
writes change the forward computation. Locality therefore has to be measured, not assumed.
    We keep the two ingredients of the original programme: characterize a transformer that has been
converted to ePC form, and build a continually learning cap. The cap is built and evaluated on the
BP model first, so that useful results do not depend on another successful conversion. The following
are treated as three separate questions rather than one bundled comparison, because each has its
own confounds:



                                                    4
  1. Routing. Does delivering credit to a bank chosen by a measured intervention effect outperform
     delivering it to every bank, and also outperform choosing a bank at random with the same
     sparsity? Does it protect private mechanisms while still allowing transfer through shared ones?
     The random control is what separates “choosing well” from “writing less.”
  2. Representation. Holding the credit rule (adjoints) and the key type fixed, does replacing the
     BP base with the converted ePC base change cap performance? This isolates the conversion
     itself.
  3. Credit and retrieval. On the same ePC base, do settled errors improve on adjoints as a credit
     signal? Do error-derived keys help beyond a matched control that uses gradient-derived keys of
     the same dimension, once their query-time and storage costs are charged?
    The guaranteed deliverable is one reproducible integrated report containing valid results, their
limitations, and the failures along the way. A routing paper or an ePC substrate note follows only if
the evidence warrants it. The multilevel predictive-coding architecture of the July design document
remains the destination; this month establishes a dependable experimental base for it.


2     Background
2.1   Two ways of assigning credit
Credit assignment is the problem of deciding how a learning system should change after a wrong
prediction. A gradient answers this for each parameter: it says how much the loss would change under
a small nudge of that parameter. Backpropagation computes gradients by the chain rule, composing
local derivatives along every path from the loss back to the parameter. Nothing in the network keeps
a record of the errors it made; the gradient is computed, used, and discarded. But this is a convention,
not a limitation: gradients can be recorded, analysed, and used to gate learning. Persistent error
records are therefore not something only predictive coding can offer, and any advantage claimed for
predictive coding has to be shown rather than assumed.
    Predictive coding (PC) networks represent discrepancies explicitly. Each layer holds error units
comparing what the layer predicted with what was actually inferred. A common PC learning cycle
has two phases: first the activities are relaxed to reduce an energy (the total squared error, in the
simplest version), and only then are weights updated from the resulting local signals. This “infer,
then update” structure and the availability of local error signals make certain architectural choices
natural, such as changing only the parts of the network that are surprised. Whether these choices
reduce forgetting in practice depends on the model, the learning dynamics, the retrieval mechanism,
and the data. One known difficulty with state-based PC implementations is that credit propagates
slowly through depth. Our Coupling Dilemma note [3] motivates studying both this propagation
problem and the interference problem together.

2.2   Error-based predictive coding
Error-based PC (ePC) reorganizes the inference phase. Instead of adjusting activities and reading
off errors, it treats the errors themselves as the unknowns to be optimized, and reconstructs the
activities forward from them. This avoids the exponential decay of signals through depth that slows
state-based PC.
     One detail matters for this programme and is easy to get wrong. The cited digital implementation
[6] optimizes the errors using reverse-mode automatic differentiation; only the weight update afterwards
is local. So a claim that ePC has “local plasticity” is not a claim that settling performs no backward
computation. When we compare costs, the preflight therefore records forward evaluations, reverse
evaluations, settling iterations, peak memory, and wall-clock time for every credit procedure, and we

                                                   5
do not describe settling as free. Nor does fast settling in the cited experiments guarantee that eight
iterations suffice for the transformer used here; that is measured.
    The internal causal-fibres report [5], as summarized in the original plan, reported a per-token KL
divergence to the teacher near 3 × 10−5 (that is, the converted model’s next-token distribution is
almost indistinguishable from the original’s), a cosine similarity above 0.998 between settled errors and
adjoints (the two credit signals point in nearly the same direction), and error mass less concentrated
in the last block than in the earlier R8/R9 runs. These are starting claims to reproduce, not results
this revision has verified. The strong alignment makes a controlled credit comparison particularly
informative: if the two signals nearly coincide, any difference in cap behaviour must come from
something else, such as the geometry of the retrieval features or the behaviour of finite-iteration
inference, and those are things we can test directly.

2.3    Caps, and what cap v0 is and is not
Adapters and LoRA [11] add small trainable pieces to a model (LoRA adds low-rank weight deltas).
Lifelong model-editing methods go further and store corrections in a memory. GRACE [7] keeps a
discrete key–value memory at one layer: each entry has a key, a value that replaces or shifts the hidden
state, and a radius; a query fires an entry when it falls within the radius, and conflicts are handled by
shrinking radii. WISE [8] instead keeps a parametric side memory derived from a feed-forward value
matrix, routes queries between the main and side memories, and shards and merges knowledge across
edits. Their memory representations and resource costs differ, so a fair comparison must measure
those costs rather than count “edits.”
    Cap v0, the cap of this month, is a PC-motivated gated activation memory: it stores local
corrections in radius-gated slots at three depths and receives credit that is either an adjoint or a
settled ePC error. It does not contain a separate cap-level energy with an infer-then-update state
dynamics of its own. This matters for how results are described. Calling an output residual “explicit,”
or weighting an update by a loss statistic, is not sufficient to establish a predictive-coding mechanism
inside the cap. A future genuine PC cap must specify its own energy, its inference variables, its
convergence procedure, and its plasticity rule. None of the routing results below depend on adopting
that stronger label, and the report will not use it.

2.4    Continual learning
Continual learning means acquiring information from a stream, one item after another, with bounded
retained state and without going back to retrain on everything. We measure immediate acquisition
(did the item get learned when it was presented), final retention (is it still known at the end),
paraphrase performance (is it known under rephrasing), locality (are unrelated inputs unaffected),
forward and backward transfer (did earlier learning help or hurt later items, and vice versa), and the
ability to acquire new items late in the stream, since some systems lose plasticity as they fill up [13].
    Two cautions shape the metrics. First, a model that learns nothing has zero forgetting, so retention
and order invariance are always reported together with acquisition; a low forgetting number on its
own means nothing. Second, when a stream contains an explicit correction of an earlier fact, the
two answers cannot both be right; corrections are evaluated against the latest valid fact, not against
every answer ever supplied.

2.5    Error highways and order effects
An error highway supplies credit to write sites far from the output, so that banks at early depths
can learn. The programme tests three delivery rules: full delivery to all banks, measured selection of


                                                   6
one bank, and sparse random selection of one bank. The measured router asks a simple question:
where does a small trial write improve the current loss? That is an intervention effect. It is not
automatically an identification of the latent mechanism that produced the error. A late bank can
almost always shift the output logits in a helpful direction, whatever caused the mistake, so “the
probe helps here” and “the error originated here” are different statements. The connection between
measured routing and the causal routing proposed in [1] is therefore a hypothesis, tested on controlled
fixtures where the causal structure is known by construction.
    The same care applies to how interference is measured. Let Ui denote the complete update the
learner performs for item i, including allocation, radius changes, and eviction, not just a gradient
step. Order dependence is observed directly: starting from the same cloned state, apply Uj after Ui
and Ui after Uj , and compare the two resulting predictions. For the special case of smooth gradient
steps Ui (θ) = θ − ηgi (θ), expanding to second order gives
                         Uj (Ui (θ)) − Ui (Uj (θ)) = η 2 {Hj gi − Hi gj } + O(η 3 ),               (1)
where gi and Hi are the gradient and Hessian of item i’s loss. This expression is worth staring at: it
involves the gradients, not only the Hessians. So commuting Hessians alone do not imply commuting
updates. The smallest possible example makes the point. For L1 = θ2 /2 and L2 = (θ − 1)2 /2, both
Hessians equal one and so commute trivially, yet g1 = θ and g2 = θ − 1, and the order difference is
exactly η 2 : each step contracts toward a different minimum, and it matters which contraction comes
second. Hessian commutators, the object studied in the Shadow Calculus note [4], describe a more
restricted linearized phenomenon; Appendix D.9 states exactly what they can and cannot tell us.
Two further points keep the interpretation honest: zero order dependence does not imply an absence
of sharing, since shared parameters can support commuting updates; and the Shadow Calculus is
motivation for the measurements, not a substitute for checking the hypotheses in the implemented
system.

3.2   Lessons from earlier runs
The reported R8/R9 runs reached low distillation energy while concentrating credit in the final
block and collapsing the internal rank of the representation; energy descent alone did not certify

                                                     7
a usable model. The August preflight reportedly failed feedforward fidelity despite deterministic,
energy-monotone runs. The CMCP comparison was reportedly confounded by unequal distillation
mass between arms. These experiences motivate four habits used throughout: functional preflights
(does the model compute what it should, before anything else), geometry diagnostics (is the internal
representation intact), matched exposure (arms see the same data), and explicit resource accounting
(arms are charged for what they consume).
    One further lesson is about how failures are read. A failed experiment does not by itself establish
that the implementation, rather than the idea, was at fault. Each failure is classified, with evidence, as
one of four things: a reproducible implementation defect, a resource limitation, an unmet assumption,
or a valid negative result. Development may repair a demonstrated defect; confirmatory results are
not re-tuned until a hypothesis passes.

5    What makes a base cap-friendly
The substrate report card is a set of six measured properties of a base. They play three different roles,
and the roles must not be confused. A validity requirement says whether a base computes what it is
supposed to; failing it makes results on that base uninterpretable. A resource eligibility criterion says
whether a base can be run within budget. A scientific descriptor is something we measure because
we hypothesize it matters, and whose relation to cap performance is itself under test. Only the first
two can exclude a base from a comparison.

    P2, geometry guards against the R8/R9 failure: a base can match the teacher’s outputs while its
internal representation has collapsed to a few directions, leaving a cap nothing to read. Effective rank
measures how many directions carry variance; a linear probe measures whether simple information
(part of speech, or a latent label on the synthetic grammar) is still linearly readable. Both are alerts,
not exclusion criteria: lower effective rank can be useful compression rather than damage, and a
probe drop may or may not matter to the cap. An alert triggers a fixed diagnostic, not the silent
removal of a working model.
    P3, localization asks where the error mass lives. A cap benefits from error fields that are sparse
per example. But per-example sparsity can hide a systematic problem, namely that every example’s
mass sits in the same single layer; so we also report layer coverage across the dataset.
    P4, structure asks whether the error vectors from different domains or mechanisms occupy
different subspaces. Principal-component overlap between domains is descriptive: nearly orthogonal
private subspaces may make selective writes easier, but overlap does not make routing impossible,
because distributions, nonlinear features, and context can still distinguish inputs. And shared
subspaces can be beneficial; they are what transfer runs through. So no domain-overlap number is
penalized indiscriminately. The decisive evidence is the effect on retained and transferred knowledge,
measured by interventions.
    P5, write locality measures one particular kind of edit direction: how much a write along the
base’s own credit direction improves the edited prompt, and how much collateral damage the same
write does elsewhere. It is one substrate advantage among several possible ones, not the whole story.
    P6, cost and informativeness records what settling costs and whether the error magnitude is
associated with the loss. A correlation is an association; it is not a calibrated uncertainty estimate
and is not called one.

    Two general cautions apply to the whole card. Error norms and PCA geometry depend on
coordinates: on layer scales and on the convention used for error precision. The wrapper records
those conventions, and every comparison uses the same observation and intervention protocol. And
rankings of P4/P5 across two or three bases are descriptive case studies. Repeated cap runs on one
fixed checkpoint do not create independent substrate replicates; with two or three checkpoints there
is no basis for a statistical law relating properties to performance.


6    Thread 1: characterize, then conditionally regularize
The first job is measurement. Score three credit signals on matched prompts: BP adjoints, ePC
adjoints (the converted base is still differentiable, so its gradient is available too), and ePC settled
errors. Audit the energy function, the clamping convention (how the target is imposed during settling),
the differentiation graph (what reverse-mode passes actually run), and the actual compute. Use the
existing ePC checkpoint even if no further training turns out to be affordable.
    The second job is conditional. Stage S6, a re-distillation with an added regularizer, is launched
only if development identifies a reproducible deficit and a tractable intervention for it. Two families
are permitted:
   If the deficit is localization (error fields too diffuse), the intervention is a positive participation
     penalty, which pushes each example’s error mass toward fewer cells, together with a separate
     dataset-level coverage term. The coverage term exists because the cheapest way to make every
     field sparse is to park all credit in one block, which is the R8/R9 failure; the coverage term
     discourages that.
   If the deficit is private-mechanism interference (learning one private mechanism disturbs another),
     the intervention is a synthetic, explicitly labelled private-overlap term that penalizes overlap
     only between mechanisms the fixture designates as unrelated, while preserving a supplied shared
     subspace. Broad orthogonalization of all domains is not the default, because it would destroy
     the shared structure that transfer needs.
    Whichever intervention is chosen, it is evaluated as a matched continuation pair : a plain continu-
ation and its regularized counterpart both start from the same production checkpoint and see the
same training-token sequence, optimizer schedule, and KD mass. Comparing an additionally trained
checkpoint only with the older production checkpoint would not isolate the regularizer, because
extra training by itself changes the model. Both arms of the pair must fit the conditional budget.
Appendix C specifies the objectives and their limits.


7    Thread 2: the minimal cap and its highways
The July design [2] proposes episodic, contextual, and schema levels, novelty quarantine, several
plasticity timescales, and replay. This month builds one memory level with three possible write
depths; the extra levels are deferred.
    Each bank reads a normalized residual-stream feature at the current prediction position and
writes an additive vector back at that position and depth. A slot contains a retrieval key, a correction
value, a radius, bounded metadata, and usage statistics. Memory is bounded in bytes, including keys
and metadata, not in slot counts. The reason is a capacity confound: three banks of 2,048 slots hold
three times as much as one bank of 2,048, and keys that include error features are twice as wide as
plain keys, so counting slots would let an arm win by having more memory. The v0 allocation rule is
specified explicitly in Appendix F rather than described as an exact copy of GRACE.
    The primary arms, and the confound each exists to remove:


                                                    10
C0: last-depth, matched memory.
      Only the last bank is writable, with the same total memory ceiling as the three-bank arms. This
      is a depth-access control: it tells us whether access to earlier write depths helps at all. It is not
      an implementation of local-PC credit propagation.
C1: full delivery.
     All three banks are eligible on every item. A common aggregate normalized write budget is
      divided among them, so that C1 does not simply write three times as much.
C2: measured routing.
      Small signed loss-improving probes select one bank per round, or abstain. All bases use this
      same bank-level rule.
CR: sparse random routing.
      One bank is selected from a distribution fixed in advance using development-only C2 delivery
      frequencies, with a matched nominal write budget. If C2 beats C1 but not CR, the benefit came
      from writing sparsely, not from choosing where. Realized usage and abstention differences are
      reported, because C2 may abstain on a round while CR’s schedule is fixed in advance, so the two
      arms can differ in how much they actually write.
CO: supplied routing.
      On the constructed modular fixture, the permitted banks are supplied to the router. This is a
      mechanism positive control and an upper reference for that fixture: it shows what correct routing
      could achieve there. It is not a real-text baseline.
    Two refinements. A smaller 2,048-slot last-bank arm is optional and is labelled as capacity-
unmatched. And if CR and C2 end up with materially different realized write counts, a development-
calibrated thinning control (CR with its writes thinned to C2’s realized rate) is reported as a diagnostic;
unobserved test labels or future C2 decisions are never used to set CR’s schedule, because that would
leak information from the test stream into the control.
    A subtle point about keys. The primary keys are computed from the current edited forward pass,
that is, with the cap’s earlier banks already writing. This means learning in an earlier bank can move
the retrieval features seen by a later bank, even though the base’s weights are frozen. This retrieval
drift is logged, and a selected ablation reads keys from a separate cap-disabled pass instead, charging
the cost of the extra pass. Error-based keys are a later, separately controlled ablation.
    Finally, the scope of what changes. Highways change how credit is delivered to the cap. The cap’s
writes do change the forward computation when the cap is enabled; that is how it has any effect. Base
parameters stay frozen, and no long-range generative connections are added to the base this month.


8    Measuring continual learning
Three test beds are used. They answer different questions, and no one of them could replace the
others.

Constructed modular control. A small fixture with explicit shared and private modules and
masked, known causal paths, so that the correct routing is known by construction. It answers two
questions that cannot be answered on a real transformer: can correct routing help at all, and does
our measurement code recover an identifiable case when one exists? It is a check on the apparatus
and on the idea’s coherence. It is not presented as evidence that a transformer’s mechanisms are
equally localized.

Learned synthetic grammar. The existing learned transformer receives tasks with shared and
private latent switches. Task context is observable in the input, so identical available information

                                                    11
never requires incompatible labels (a stream that asked the model to give two different answers to
identical inputs would be unlearnable by anyone, and would measure nothing). Attribution of a
latent cause to a depth can span several depths on a learned model, and ambiguous tracing outcomes
remain in the report rather than being tidied away. Held-out combinations of switches test transfer,
including whether selective learning preserves the shared mechanisms.

Sequence-level editing. zsRE and CounterFact are run as separate streams, with complete answer
strings, aliases, paraphrases, and near-neighbour locality prompts. The ceilings are 3,000 zsRE edits
and 1,000 CounterFact edits per stream realization; the confirmatory prefix length is chosen from
throughput measurements before testing. Edits are learned and evaluated as complete generated
answers, not single tokens: a first token can be correct while the rest of the answer is wrong, and a
single-token benchmark cannot see that. A single-token subset may serve as a development smoke
test, labelled as such. Appendix E fixes the autoregressive training and free-generation evaluation
protocol.

Baselines. B0 is the frozen model, which sets the floor; B1 is sequential LoRA with no protection
against forgetting; B3 is LoRA with a bounded reservoir replay buffer, the standard practical defence;
B4 is GRACE, adapted from its authors’ implementation and the closest published relative of the cap.
B2 (LoRA with EWC [12]) and B5 (WISE) are optional. All run locally under the shared harness;
published scores at other scales are never substituted. A joint-training reference on the synthetic
fixture estimates the performance attainable with all data at once, without being assumed to be a
mathematical ceiling.

Metrics. Immediate and retained acquisition, paraphrase retention, forward and backward transfer,
locality, language-model drift, learning late in the stream, memory occupancy, evictions, update
norms, runtime, and per-example order dependence. Order dependence is measured directly by the
cloned-state probes of Section 2.5, which capture positive as well as harmful changes. Near-neighbour
prompts, compositions of learned facts, and explicit corrections receive separate challenge evaluations.
One principle runs through all of this: similar aggregate scores do not imply similar predictions, so
the report keeps the per-item information needed to see which items were lost.

9.2   Predictions and interpretations
Each prediction is stated with what a positive and a negative result would mean, because the meaning
of a null is where interpretation most often goes wrong.
PR-A: depth access.
     At matched total memory and nominal write budget, earlier write sites may improve acquisition
     or transfer relative to C0. A null means no demonstrated depth-access advantage in this setting,
     not the failure of all local-PC approaches.
PR-B: routing.
     C2 improves retained paraphrase accuracy relative to C1 and to CR, with acquisition and
     locality noninferior as specified in Appendix D.11. Reduced direct update-order harm and
     reduced private-mechanism damage are supporting outcomes. Failure to outperform CR blocks
     attributing an advantage to measured selection rather than to sparse writing.
PR-C: causal agreement.
     On the constructed fixture, C2’s routing precision and recall against the supplied permissions
     target 0.8. Below 0.6 is poor agreement; 0.6–0.8 is partial. Uncertainty intervals are reported.
     Failure here is a scientific outcome once the fixture and oracle controls pass, not an implementation
     failure. Tracing on the learned transformer is evaluated separately and is not called ground truth.
PR-D: substrate and credit.
     SE-A versus SB and SE-E versus SE-A test separate hypotheses. An error-key claim additionally
     requires its feature control (R-g) and its resource accounting. Results are conditional on fidelity
     and on the particular cap tested.
PR-E: property association.
     The P4/P5 scores and retention may covary across checkpoints. With two or three checkpoints
     this is descriptive, not a validated predictive law.
    For the intended account of shared and private learning, both beneficial transfer and reduced
harm are needed; reduced harm alone could be achieved by learning less. No Hessian statistic on its
own constitutes success.

The schedule follows a development-then-confirmation shape. In development, we may look at results

endpoints will be read, and the analysis code. After the freeze, confirmatory data are touched once.
The purpose is to prevent the most common way that experiments fool their authors: adjusting the
analysis after seeing which version of it looks best.

11     Risks and traps
Misattributed advantages. Sparse writing, larger memory, useful retrieval features, and extra
compute can each improve results on their own. The matched controls and one-change-at-a-time
contrasts exist so that the report can say which of these explanations the evidence supports and
which it rules out.

Retrieval drift. Earlier writes move the features that later banks key on. We log key displacement,
retrieval changes, duplicate allocations, and their causes, and compare against stable (cap-disabled)
keys when the drift looks material.

Unlearnable ambiguity. Conflicting labels without any observable context cannot all be retained
by any method. The synthetic generator therefore exposes task context, and true corrections follow
an explicit revision protocol and are excluded from claims about invariance to item order.

Metrics without acquisition. Low forgetting, small commutators, or stable outputs can all result
from weak learning. Acquisition and retained accuracy are always reported together. Correctly
rejected updates and abstentions are outcomes, recorded with codes, not hidden as exceptions.




                                                   14
 Resource assumptions. Intervention probes, backward evaluations, settling, and per-token-prefix
 updates can dominate cost. Measured throughput, not hope, determines stream length; nominal
“steps” are not comparable units of computation across methods.

Premature certainty. A negative P5 result does not exhaust the substrate hypotheses, and an
attractive PCA pattern does not establish causal modularity. Every conclusion in the report states
its assumptions and the range over which it was tested.

A    Operating rules
 1. Read and instantiate. Read the complete plan. S0 records checkpoints, datasets, hardware,
    exact dependencies, and missing assets. A missing optional asset does not block unrelated valid
    work. Reason: most implementation failures in earlier runs came from acting on part of a
    specification.
 2. Three classes of decision. Correctness controls test code; resource limits delimit feasible
    execution; scientific outcomes test hypotheses. A scientific null never becomes a code failure
    merely because it is undesirable. Reason: treating a disappointing result as a bug invites tuning
    until the result pleases.
 3. Bounded development. Stages S0–S3 use development-only examples and at most the
    calibration candidates listed in this contract. Log every attempted configuration, including
    failed ones. No confirmatory prompts or labels are used to choose configurations. Reason: a
    configuration chosen by looking at test data is a result measured on its own training data.
 4. Freeze before confirmation. S4 commits a machine-readable manifest containing all numerical
    choices, hashes, randomization, the complete list of comparisons, the order in which endpoints are
    read, stopping rules, and analysis code. A later bugfix creates a new version: retain the affected
    old results, and rerun all affected paired arms if affordable; otherwise mark the comparison
    incomplete. Reason: a comparison whose two sides ran on different code is not a comparison.
 5. Correctness failure. Stop only the affected run or mechanism. Record the failed invariant, at
    most three diagnoses, and the cheapest test that separates them. A demonstrated implementation
    bug may be repaired within the development budget. Scientific thresholds cannot be relaxed to
    manufacture a pass. Unresolved changes to task scope go to the human lead. Reason: halting
    everything on one failure wastes the month; relaxing a threshold destroys the meaning of passing
    it.
 6. Shared measurements. Use the same harness, evaluation prompts, tokenization, answer
    normalization, stream order, and revision metadata for every arm in a comparison. Missing
    metrics are explicit and are never replaced by arm-specific approximations. Reason: two arms
    scored by different code can differ for reasons that have nothing to do with the arms.
 7. Honest resource matching. Report the exposure-matched and resource-matched views
    separately (Appendix B). An equal count of updates is not an equal count of FLOPs. Include
    replay, routing probes, line searches, and retrieval in the accounting. Reason: a method that wins
    by spending three times the compute has not been shown to be a better method.
 8. No silent fallback. Exceptions and unexpected nonfinite values are logged with stack traces
    and the affected items. Mathematically undefined ratios receive a structured undefined value
    together with their operands; these are not NaNs in the computation graph. Ordinary rejection,
    eviction, unreachable targets, and ambiguous items have explicit outcome codes. Reason: a
    fallback that changes a number without saying so turns a failure into a fabricated result.
 9. Reproducibility. Replaying the same configuration, input stream, and initial random state
    twice must reproduce discrete decisions and metrics. Use deterministic kernels for the small


                                                 16
    controls. Where numerical nondeterminism is unavoidable, identify the kernel, require a metric
    tolerance of 10−6 relative or 10−8 absolute, and report decision disagreements rather than
    concealing them. Dropout is disabled in base evaluation and in cap probes. Reason: if two runs
    of the same thing differ, no difference between two different things can be trusted.
10. Frozen base. Hash base parameters and persistent buffers before and after each run. Cap-off

    failures, exclusions, and interpretation. Stop at the resource ceiling and preserve checkpoints.
    Never continue sampling seeds because a significance threshold was almost reached. Reason:
    adding seeds until a threshold is crossed guarantees crossing it eventually, whether or not the

D     Metric definitions
All metrics are computed by the shared harness. Accuracy-like scores are fractions, so a “two-point
margin” means 0.02. Use natural logarithms throughout. Store numerators, denominators, sample
counts, and exclusion reasons with every ratio. For schema purposes undefined, unreachable, and
not-supported are distinct outcome codes and are distinct from an unexpected floating-point NaN.
Reason: a ratio without its operands cannot be audited; an undefined value that is silently replaced by
zero or by a large number changes an average.

D.1 Fidelity (P1)
Compute KL(pT ∥pS ) between teacher and student next-token distributions, averaged over H at the
same teacher-forced positions: first with no settling, then without a target clamp after eight iterations.
An eligible matched-fidelity comparison requires both means ≤ 10−3 nats per token. Report also

  5. Transactional update search. If b banks are scheduled, reserve A/b for each, with no
     redistribution of unused shares. Process them in increasing depth order. Recompute current
     features, gates, loss, and credit after each accepted earlier-bank write. Resolve the candidate
     bank’s conflict or allocation in a private transaction as F.2 specifies, preserving the pre-transaction
     state as the no-op option. Candidate incremental values use

                        ∆vs = ws a bm dm ,       a ∈ {A/b, A/(2b), A/(4b), A/(8b)}.

    Here ws = 1 in the primary protocol; any optional difficulty weight is already included in the
    tested update. For a new slot initialize its value to zero before the candidate increment. Test

      candidates from the same original transaction snapshot, not cumulatively. Evaluate the actual
      resulting cap with all ordinary retrieval rules. Choose the candidate with the smallest loss,
      breaking ties by the smaller normalized increment; commit it only if the loss improves by more
      than max(10−8 , 10−6 L). Otherwise restore the complete original state. There is no assumption
      of monotonic loss along a direction and no requirement that a fixed 90% reduction be reachable.
      Reason: a geometric candidate grid with a no-op option is a bounded line search that cannot loop,
      cannot assume convexity, and always has a safe outcome.                      P
  6. Budget accounting. The sum of normalized accepted value increments m ∥∆vm ∥/bm is at
      most A per round. This is a cap parameter-write budget; radius changes, evictions, and gate
      switches can produce additional functional changes, which are measured separately. Rejected
      searches and routing probes consume compute. A forced probe is never retained as an unlogged
      learned write. The primary search uses at most four forward candidates per scheduled bank per
      round; all call counts are recorded.
  7. Metadata. After commit, update the target token, owner digest, version, use count, and last-use
      index consistently. The optional loss EMA uses the pre-update loss of the item that actually used
      the slot, with rate 0.2. Never initialize it from a conveniently small fitted residual and call it
      Bayesian precision. Repeat from a fresh forward pass, or stop at the threshold or at the round or
      resource limit.
The optional difficulty arm sets ws = max(0.1, 1/(1 + L̄s /Lref )), with Lref > 0 fixed on development
data and L̄s the prior pre-update-loss EMA; new slots use ws = 1. This is a heuristic sensitivity
analysis, not a variance estimate. Every committed candidate already includes ws in its measured
loss.

F.5 Positive controls and failure semantics
PC-1: planted acquisition.
     On the constructed fixture, the supplied router and known attainable edits recover at least 19 of
     20 targets within the round budget. Supply the exact support for the invariant portion of this
     test. Unrelated outputs remain unchanged to the declared numerical tolerance.
PC-2: support and cap-off identity.
     An oracle gate that is false on unrelated inputs produces exactly their cap-disabled computation.
     With the whole cap disabled, outputs match the base reference on 256 probes. A checksum alone
     is not a behavioural identity test.
PC-3: repeat idempotence.
     For 20 edits that reached the per-prefix threshold, with no intervening updates, repeating the
     same complete edit allocates no additional slots. It need not have had only one slot initially.
PC-4: conflict transaction.
     On hand-built distinct-key conflicts, the old value and key survive, radii remain nonnegative,
     and failed replacements roll back every change. Test identical-key ambiguity, a supplied newer
     version, and repeated delivery of that same version separately.
PC-5: signed probe and search.
     On an analytic one-dimensional loss, a helpful probe has a positive score and a harmful probe a
     negative score. A nonmonotone test loss does not crash and is not assumed to bracket a root.
     Rejection restores the exact learner state. The accepted update is precisely the one evaluated,
     including any difficulty weight.
PC-6: memory and write budgets.
     C0/C1/C2/CR respect the same total byte ceiling; R-e/R-g keys reduce the allowable slot count
     as required. Verify aggregate normalized increments and deterministic eviction at full capacity.
PC-7: complete answers.
     A two-token answer with the correct first and incorrect second token fails ES. Teacher-forced
     success does not override free-generation failure. Terminators and truncation follow the common
     policy.
PC-8: label isolation.
     Query features receive only the input prefix and the base-derived pseudo-label. Changing a
     hidden evaluation answer while holding the prefix fixed cannot change R-e/R-g keys or the
     prediction. All evaluation is read-only and leaves the complete learner state unchanged.
PC-9: cloning and randomness.
     Cloned identical update sequences agree; reversed sequences begin from the same complete state
     and use the declared item-keyed random choices. The scalar quadratic order effect is recovered.
PC-10: reference parity.
     Validate GRACE and other baseline adaptations on small shared single- and multi-token cases,
     documenting intentional changes such as memory eviction. Baseline underperformance is not a
     parity test.
Router accuracy on the learned grammar, superiority over LoRA, and any particular PCA pattern
are scientific measurements. They are deliberately absent from this list of implementation invariants.

F.7 Package interface
The package pccap supplies BPBase, EPCBase, Bank, Cap, Router, Transport, the fixtures, and
Harness. Base wrappers expose forward, hidden hooks, adjoint, finite error inference, checksums, and
a per-call cost record. Cap exposes read-only predict, transactional update, serialize, restore, clone,
and memory-bytes. Router variants are Last, Full, Measured, Random, and Supplied. Dataset
manifests separate development and test. All configuration paths and hashes are explicit.
     pccap run --stage S4 --arm C2 --base BP --read h
       --realization 0 --perm 0 --manifest frozen.json

The command fails if a required frozen field is missing. Decision records carry item digest, prefix
and round, candidate banks, signed scores, chosen route, accepted increment, before/after loss,
allocation/conflict/eviction codes, and all cost counters. They contain no undisclosed evaluation
answers in inference features. Human-readable logs and machine-readable outcomes agree.
