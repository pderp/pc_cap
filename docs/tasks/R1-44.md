## Population and selection

At a declared checkpoint, evaluate **one original edit-style prompt per source item whose fact has not been edited**. Queries come from the same admitted, hash-bound pool as the stream edits, not NQ locality or another dataset. The caller supplies explicit item IDs; this module never samples, opens a dataset, teaches a support, or emits a file.

The constructor copies only item ID, fact ID, normalized subject, prompt and dataset. Answer strings, aliases and answer token arrays are ignored; changing those fields leaves query metadata and outcomes unchanged in the tests. The caller supplies the admitted source file SHA-256; the evaluator additionally computes an ordered query-metadata hash and hashes the complete edit history and requested query-ID list.

The full edit history must include successful, failed, evicted and superseded edits. Every stored fact, active or inactive, must be covered by that history. An outside item is unavailable if its item ID, fact ID, normalized subject or normalized prompt overlaps any edited item. Unknown query IDs are unavailable; duplicate requested IDs and invalid/unknown edit histories are rejected before model execution. NFKC/casefold/whitespace normalization is conservative string handling, not proof of complete alias equivalence; upstream entity/context review remains required.

For a 1,000-record endpoint with 100 outside prompts, the admitted source population needs at least **1,100 distinct appropriate facts**, plus any separate near-miss/revision reserves. The existing 1,000-item training bank cannot supply an outside denominator at occupancy 1,000. An empty outside list is never reported as perfect rejection. A fixed reserve disjoint from the entire maximum-length edit stream can be reused at 100/300/1,000 for a paired scale diagnostic; source admission and prompt identities must be fixed before outcomes.

## Metrics and denominators

| Measure | Numerator | Denominator and interpretation |
| --- | --- | --- |
| False-fire rate | Outside prompts whose actual hard gate accepts memory | All planned outside prompts with observed decisions; full-inventory rate is null unless every planned decision is available. Acceptance need not produce a nonzero write or change the answer. |
| Bounded answer-change rate | Cap-on decoded text differs exactly from this condition's cap-off decoded text | All evaluable outside prompts, irrespective of firing or acquisition. Exact text equality follows the existing LS comparison convention. |
| Complete-answer preservation | Both generations terminate and decoded texts are identical | All evaluable outside prompts; truncated pairs cannot count as complete preservation. |
| Change among complete pairs | Text changes among pairs where both generations terminate | Complete-pair diagnostic only; its smaller denominator is explicit. |

Each output records expected/requested/scored counts, source shortfall, status counts, coverage, firing-observed count, incomplete answer pairs and integer numerators. Evaluated fractions are distinguished from full-inventory fractions. If any planned case is missing, unavailable or a recorded resource failure, the corresponding full-inventory fraction is null. No failed case is silently replaced, and unavailable firing instrumentation is not counted as zero fires.

The primary bounded decode policy is the shared greedy decoder, at most 32 new tokens, newline/EOS stopping. Both outputs' text, termination, truncation, step count and costs are retained; token-sequence change is also reported. No stored “correct answer” is used as the preservation reference. For a continued-base condition, use that condition's cap-off base; language-model drift from the original base is a separate endpoint.

**This differs from LS:** existing zsRE locality largely uses NQ prompts; CounterFact locality uses relation neighbours. The new population consists of plausible *edit requests about absent facts*. Good LS can coexist with high unseen-edit-prompt firing. Gate acceptance, text change, complete preservation and ordinary LS are distinct outcomes.
