## Owner entry points

From pc_cap, use the existing venv and module execution:

```bash
python -m scripts.r1_61_cell_driver --manifest PATH --manifest-sha256 SHA256
```

The default inspects recipe metadata only. It does not open the payload or construct a model. The owner later adds `--execute` after admission and resource coordination; `--resume` requires `--execute`. Do not run the example recipe: all approval and source placeholders are deliberately unbound.

## Practical limits and required owner validation

This is a sequential correctness-oriented driver. The previous profile estimate does **not** measure its extra hashing, cloning, immutable phase-file output or full assay workload. Measure a real cell before adopting a ceiling or extrapolating wall time. Per-phase files deliberately preserve interrupted work; large matrix runs will produce many files.

Returned counters from TinyBase are exercised even though that fixture does not populate the real base's shared ledger. Costs from different attempts remain separate auditable records; the final attempt's ledger alone is not the total cost of a resumed cell.

Scientific admission, the final resource ceiling/watchdog, real-base validation, GPU leases, final population/seal creation and actual launch belong to the owner. The driver does not select data, fabricate challenge semantics or waive resource/fidelity gates.
