# R1-49l — fidelity-limit provenance and classifier interpretation

**Status: complete audit; a lead scope decision is required before final admission.** Codex, round 32, September 18, 2026. No threshold, protocol, implementation policy, decision row or running source was changed by this lane.

## Finding

The strongest explicit original registration is **(a): fidelity of the changed/continued base with the cap disabled**, including S1 and prospective episodically trained bases. The governing guide specifies that state; DEC-033 adopts plan 9 with that guide as the specification, and DEC-047 certifies a continued base using the same interpretation. The Q12 proposal later accepted by DEC-058 still explicitly says **“For continued-base fidelity”**.

Cap-on ordinary-text drift is separately required and must be measured. However, I found **no explicit lead decision extending the .001 mean-KL limit into an automatic admission veto on every cap-on final checkpoint, against both references**. Draft v5 moved unqualified fidelity wording into the cap-drift section; v5.1 and its successors inherited that ambiguity. My D.2 text made the extension explicit, and my round-31 implementation made it an automatic veto. That is a scope expansion, not merely retaining a number. D.2's claim that it “changes no classifier” is incomplete: DEC-058's inequalities stayed the same, but the input admission predicate changed which labels can be reached.

Therefore the history is **originally (a), later ambiguous prose, currently implemented (c)**. Treat the added cap gate as requiring an explicit lead decision. The measured .0055436876 remains valid development evidence. My previous explanation correctly described the current numerical check but overstated that this cap-enabled use was unambiguously registered originally.

## Exact primary-source sentences

The [coding-agent guide](../more_input/pc_cap_coding_agent_guide%20%281%29.pdf), PDF page 5, defines:

> L_fidelity: teacher-to-student KL on ordinary text with the cap disabled.

The same guide, PDF page 8, supplies the numerical proposal:

> For base fidelity, start from mean teacher KL at most 0.001 nats/token and ordinary-text loss increase
> at most 0.01 nats/token on a specified held-out set. Tune only in development; a justified alternative
> threshold requires a new frozen specification.

The [joint redesign proposal](../more_input/pc_cap_joint_redesign_proposal%20%281%29.pdf), page 2, states:

> Teacher fidelity applies to ordinary base behavior; revised questions are scored against the new
> information. This avoids asking the edited system to reproduce an obsolete teacher answer. Final
> evaluation must use facts and entities excluded from training.

This last passage separates ordinary-text preservation from intended factual changes, but does not specify a cap-on .001 admission threshold. The guide provides the more precise cap-disabled definition.

[Plan 9](../updated_plan9.md), Stage 2 exit, says:

> Exit: a reproducible change in held-out editability with fidelity retained (teacher KL ≤ 1e-3 nats/token; ordinary-text loss
> increase ≤ 0.01 on the declared held-out set), or a clean negative.

Its D-R3 row says:

> Proposed confirmatory margins (RET-GS +0.05, ES −0.02, LS −0.01) and fidelity bounds (KL ≤ 1e-3, loss increase ≤ 0.01) to be frozen after development

The [DEC-033 row](../decisions.md) adopts:

> D-R1 the plan is the contract with the coding-agent guide as specification

and:

> D-R3 margins RET-GS +0.05 / ES −0.02 / LS −0.01 and fidelity KL ≤ 1e-3, loss increase ≤ 0.01, frozen after development

These broad plan/decision summaries do not explicitly override the guide's cap-disabled state. Reading the bounds alone cannot settle which comparison they constrain.

[DEC-047](../decisions.md) is concrete application, not a cap-on extension:

> **S1_LM certified**: the informative LM continuation at weight lr 1e-8 (`r1_24_control_lm_v3_lr1e-8`) passes the pre-registered fidelity gate (KL 0.0005 nats ≤ 0.001; NLL −0.009) and is the S1_LM base for the matrix; lr 1e-6 (v2) stays on record as the failed-gate run.

The corresponding `scripts/r1_24_runtime.py:fidelity` computes logits from `original` and `continued` base parameters; no cap or episodic memory is an argument. `evaluate` separately runs cap editing and drift. [R1-24](R1-24.md) explicitly distinguishes 8,192 OpenWebText base-fidelity targets from 16,256 cap-drift validation targets.

Most decisively, the [Q12/U13 proposal](R1-49f-lead-bindings.md), accepted as proposed by DEC-058, says:

> For continued-base fidelity, retain the accepted upper limits: mean KL at most .001 nats and mean
> signed loss increase at most .01 nats on the frozen validation population. Equality **passes** these
> upper-bound checks. Both complete measurements are required; missing/nonfinite values fail admission.

It also says:

> Fidelity failure does not justify silently removing a required comparator.
> The owner records an admission failure and returns to the lead's matrix/scope decision.

The proposed insertion later in the same memo drops the modifier “continued-base,” explaining how the ambiguity propagated into v5.1. DEC-058's decision row binds classifier margins and admissibility but does not explicitly add a cap-on KL veto.

## What the installed D.2 consumer actually does

1. `r1_63l_full_validation_contract.summary` computes both-reference fidelity using the joint mean-KL ≤.001 and mean-signed-NLL ≤.01 test. It distinguishes complete observations from missing/invalid vectors.
2. `r1_75_analysis_stage4_v1.load_cell` preserves `status="complete_artifacts"`, primary metric values and `full_validation_complete=True` for a valid measured failure. It sets `full_validation_fidelity_passes=False`, then makes `scientific_admission=False`.
3. `r1_49g_inference.primary_contrasts` still computes complete paired estimates, realization means, adjusted intervals and unadjusted intervals when the planned primary data are complete. Failed fidelity alone does **not** erase those calculations or create missing population rows.
4. It passes the failed admission to `classify`, which returns **`unavailable` before testing DEC-058's negative/positive/qualified/inconclusive inequalities**. There is no separate `fidelity_failed` primary classification. An observed fidelity failure is therefore visible in cell fields but conflated with other admission failures at the final label.
5. One failed primary cell makes all seven comparisons sharing it in that dataset unavailable. One failed control cell affects only that control's comparison. Other datasets can remain classified. The 63-interval family is unchanged.
6. MQuAKE's 1,000-edit comparisons are already **unavailable under DEC-060**, independently of fidelity: its declared final endpoint is 300. The current development profile cannot fill any confirmatory slot regardless of whether its cap fidelity passes. It is not justified to extrapolate this one development run into a predicted failure of every future confirmatory cell.

The new synthetic rehearsal proves these branches: all 14 zsRE/CounterFact contrasts are positive with complete admitted synthetic data; withholding one zsRE primary cell's admission makes its seven labels unavailable **with identical numerical metrics/intervals**; withholding one v0_stable control affects one; all seven MQuAKE primary labels remain unavailable. A cell-level receipt fixture verifies passing, complete-failing and absent-full-endpoint states separately. A failed admission also takes priority over otherwise-negative DEC-058 metrics.

This numerical veto was connected in round-31 commit `73ff6b0`: [exact diff](../../logs/r1_round32/provenance/round31-admission-change.diff). Previously `scientific_admission` required confirmatory scope, admitted recipe and complete primary metrics; it did not inspect a per-cell full-validation fidelity result. D.2 is therefore an observable behavioral change even though no number or DEC-058 inequality changed.
