The separate development runner retains the existing checkpoint engine's immutable phase/attempt logs, charged failures, read-only assay restoration, authenticated snapshots and contiguous-receipt resume. It is an explicit source fork of the R1-61 engine, with shared assays/adapters and structural inventory checks; the sealed CLI/module remain unchanged. This avoids editing another lane's existing code. Future engine repairs should be reconciled across both implementations. The shared validator's synthetic branch is used only to check common inventory structure without opening sealed reservations; execution mode and outputs remain explicitly development.

Mode is `stage4_development_cell`. Every JSON execution artifact, phase, receipt, failure, checkpoint report and snapshot sidecar is labelled `development, not confirmatory`. Binary snapshots preserve the ordinary state format and are authenticated by labelled sidecars/receipts. Output roots must be under `results/R1/stage4_dev_cells/`; snapshot resources remain under assets. Payloads must be in the explicit unsealed development resource directory. Admission flags must be absent or strictly false; true/ambiguous values, sealed-reservation references and allow-sealed requests are refused before payload access. Production development supports 100, 100/300 or 100/300/1000 checkpoints and the 32-token decoder. Short TinyBase fixtures are explicit and refused by CLI execution.

Payload selection retains manifest order, never outcomes, and excludes duplicate subjects/IDs. zsRE/CounterFact use 300 development items; fillers and outside queries can come from training-pool rows beyond the first 1,000, following the existing profiling convention. Every filler is labelled. MQuAKE uses its 100-item v3 dev slice plus, where requested, the 500-item v3 training pool; it refuses a request for 1,000 edits because that source is insufficient. It never reaches into fresh candidate inventory to hide a shortfall.

Locality uses the manifest's unrelated prompts. MQuAKE's revised locality probes now belong to the edited dev slice, so interpret them as in-slice interference rather than an independent outside-locality assay. Near/revision rows are filtered by dataset from the existing development challenges. That file supplies CounterFact cases only: zsRE and MQuAKE retain the planned 100/50 inventories with unavailable source rows, rather than fabricating successful endpoints. Available MQuAKE composition cases require every dependency in the stream; the 100-item v3 payload admits 48 source cases. Drift defaults to 128 fixed windows of length 128 (16,256 scored next-token positions); this is development profiling, not the final full-validation inventory.
