## Re-pricing rule

A class is the exact condition, dataset, attempted-edit count, checkpoint cadence and full-validation contract. Each complete cell through the selected block contributes its **entire measured process chain**, including failed attempts followed by successful retries. No donor is excluded for failing a fidelity benchmark or an unfavorable scientific outcome. A completed cell's process envelopes must all have the requested configured worker count. Different or missing worker metadata and host-failure chains remain explicitly excluded from rate estimation, with their actual costs still charged.

The expected process cost per remaining comparable cell becomes the arithmetic mean of these completed-chain durations. Its proposed effective ceiling is **1.5 × the maximum measured chain duration**. These are scheduling estimates, not confidence bounds. Measured two-worker envelopes already contain their concurrency cost: the tool does **not** multiply them by 1.15 again. For review it also reports the corresponding solo-ceiling value as effective ceiling  / 1.15; this is a conversion to the existing queue contract, not a new isolated-worker measurement.

Unmeasured classes keep plan-v3 expected solo × the configured-worker factor, and the existing 1.5 solo ceiling × that factor. Nothing transfers from 300 to 1,000 records, between conditions/datasets, or from partial checkpoints to full endpoints without a separate reviewed rule. Whole-cell measurements replace the whole estimate once; no sampled/full/startup phase is added again. Actual spending sums every process envelope once, including overlap and failed work, replacing covered driver timers. Exhausted cells remain incomplete, contribute their spent time, and have no new retry reserved. Future unobserved failures receive no invented fixed allowance; the buffer is available to absorb them.

`expected_total = actual_spend + Σ remaining_count × class_expected_cost`.
`proposed_ceiling_total = actual_spend + Σ remaining_count × class_effective_ceiling`.
Buffer is 750 hours minus the respective total. The unchanged **active** admitted ceiling projection is shown separately. No new throughput or calendar forecast is inferred from summed process envelopes. Memory ceilings, the 6,144 MiB launch floor, October 9 stop, scope and analysis remain unchanged.

The first proposal is plan v4; pass it as `--previous-plan` at the next completed block to emit v5, and so on. Source cost receipt and immutable queue identity stay fixed within this chain. Previous accounting files cannot be rewritten or removed, the watch prefix cannot be changed, and completed evidence cannot regress unnoticed. A new admitted matrix/cost identity requires a separately reviewed new chain; do not reuse a previous plan against different bindings.

## Owner command at a stopped boundary

Run from `pc_cap`, using the **actual signed** cost receipt bound by `run_matrix_final.json`. The example names below are placeholders for the owner's actual receipt and new output path, not instructions to create signatures.

```bash
PYTHONDONTWRITEBYTECODE=1 JAX_PLATFORMS=cpu CUDA_VISIBLE_DEVICES= \
  OPENBLAS_NUM_THREADS=1 ../venv/bin/python -m scripts.r1_d12_reprice \
  --matrix manifests/revision_v1/run_matrix_final.json \
  --receipt-root logs/R1/final_queue \
  --journal results/R1/fidelity_watch/observations.jsonl \
  --cost-receipt PATH_TO_ACTUAL_SIGNED_V4_RECEIPT \
  --boundary-block 1 --workers 2 \
  --output-dir logs/R1/block1-cost-review-v4
```

For block 2, add `--previous-plan logs/R1/block1-cost-review-v4/plan.json`. Add `--previous-report logs/R1/block1-cost-review-v4/d11-report.json` only if that report was actually relayed; generation is not delivery. Omit it to display the whole watch history. `--synthetic` is for disclosed fixture rehearsal only; never use it to bypass real admission. The real mode refuses the current unsigned source receipt.

Each new output directory contains:

1. `plan.json`: exact input hashes, D11 snapshot, per-class donors and projections, proposal digest.
2. `execution-plan-vN.md`: versioned narrative/table with updated budget buffer.
3. `d11-report.json`: accounting snapshot and cursor for the next posted report.
4. `fidelity-watch.json`: global new observations/entries/alerts and explicit queue-cell attribution.
5. `dec052-inventory.json`: completed blocks, missing checkpoint cells, exhausted cells and prospective omissions.
6. `lead-queue.txt`: ready-to-post text; the tool does not post it or mark alerts delivered.

Re-pricing refuses incomplete blocks, global live/unknown costs, uncovered driver timing, missing required watch observations, changed inputs or an existing output directory. Reuse ordinary D11 status reporting while later workers are active; D11 can report a completed block with global uncertainty, whereas replacing forecasts requires complete spending. Immediate creep alerts still go to the owner without waiting for this report. Before changing ceilings, keep dispatch stopped, review the new projections and issue the required versioned admission/package; this tool cannot mutate frozen bindings or give a new plan the authority of the original signed receipt.
