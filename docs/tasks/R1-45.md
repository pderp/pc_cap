There is no negative subsampling: each item is compared with every other item's prompt in its pool. Source texts, aliases and answer labels are not used to choose positive/negative scores; only source prompt/paraphrase/locality/subject fields enter lexical features. Answers are not tokenized for this analysis. Every item has an individual record with positive/locality scores, query hashes, coverage and the mean feature values over other prompts. Complete per-feature empirical ROC curves and tie-aware AUCs are included.

Token IDs come from the local hash-verified GPT-2 tokenizer, without added special tokens and with original case/punctuation retained to match the deployed lexical feature convention. The stop list is the 200 most **occurrence-frequent** token IDs across all source prompts, all paraphrases and all locality texts in the three pools. Repeated source occurrences count; equal frequencies tie by token ID. It shares 186/200 IDs with installed `stop_tokens_v1.json`, whose declared policy uses document frequency and only the first two locality prompts. This report does not edit or silently substitute that deployed list.

Subject tokens are taken from the literal subject span in the support prompt, using tokenizer offsets. All 3,600 subjects were found literally in this inventory. Thus GPT-2's leading-space token distinction is handled in the support's actual context. A fallback is implemented and disclosed for future missing spans; it was not used here. After stop removal, one training item loses all subject tokens and receives an explicit zero/coverage flag. Relation tokens are the support tokens outside the subject span; this does not infer a semantic relation or recover an unknown neighbour subject.

## Recommendation

Use **subject-token recall after stop removal** together with **symmetric prompt-token overlap after stop removal** as the next two lexical inputs to the null head. The latter is already close to the installed scalar `lex_feature`; the first adds a direct check that a relation-matching neighbour actually refers to the supported subject. Both depend only on the query and support metadata/tokens, never on held-out answer labels.

On CounterFact development locality, subject recall AUC is 0.9800 versus 0.9566 for stopped prompt overlap; both reach 1.0000 on zsRE development locality. Subject recall remains strong when a valid CounterFact paraphrase contains a long distractor prefix, whereas the symmetric overlap also reflects how much of the query is explained by the support. They are correlated; these single-feature results do **not** establish that the pair improves the already recovered mixed-domain null. Run a matched one-feature/two-feature ablation before adding complexity.

An implementation needs a support-side subject token mask or a clearly declared subject extraction policy; the current memory stores support tokens but not an explicit subject-span mask. That is an owner-reviewed schema/byte change, not something performed by this analysis. Freeze the chosen stop-list identity and retrain/calibrate if changing it. Preserve a visible missing/empty-subject indicator rather than treating zero overlap as reliable negative evidence in that case.

I would not prioritize the relation-template feature: raw AUC is approximately 0.44–0.45 against CounterFact near-neighbours, which share the relation while differing in subject. Stop removal erases all relation tokens for 250/300 CounterFact dev items and 2,485/3,000 train items; the resulting AUC is near chance. Normalized longest contiguous span is a useful diagnostic (0.8411/0.8500 on CounterFact dev/train locality) but trails the two recommended features. It is sensitive to subject length and exact BPE spelling.

## Interpreting the ROC

The tables below use **item-balanced** AUC: each source item contributes one unit of positive mass and one unit of mass to each populated negative class, regardless of how many queries it supplies. Query-weighted curves are also in JSON. Positive means paraphrase; higher score is always the positive orientation. Ties receive half credit in AUC. No feature is flipped after seeing its score.

At false-positive rate at most 1%, stopped subject recall retains 72.7% of CounterFact dev paraphrases and 48.8% of the training-pool paraphrases; stopped whole-prompt overlap retains 30.2% and 28.4%. High overall AUC therefore does not solve the stringent locality tail. zsRE is far easier in this observed lexical population. The best-Youden thresholds saved in JSON are exploratory summaries, not adopted deployment thresholds.

These are pairwise comparisons with the item's own support, not the maximum score across a 64/100/1,000-record memory. Shared records make the millions of pairs highly dependent. Do not construct a naive confidence interval using the pair count, equate pairwise FPR with full-answer LS, or treat a low other-prompt FPR as a calibrated memory-level null. M5 still needs a fixed memory/query population and held-out development operating-point selection. The existing mixed-domain result supplies an empirical comparator; this analysis alone proves no causal effect on model answers.
