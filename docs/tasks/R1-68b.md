The new driver accepts integrity_profile=incremental or full (default full), and binds both the profile and
new runtime/driver source identities. It refuses unsupported learner families. The old driver refuses these
recipes on code identity, preventing a silently ignored incremental flag. The development engine's source
hash is pinned; any later upstream engine change requires deliberate reconciliation before use.

Mutation inventory: IndexedStore wraps add; supersede (both old and new records); remove, including reactivation;
set_code; set_delta, including None; rebuild_keys; and import/restore. Nested operations accumulate dirty IDs until
the outer operation completes, including a partially failing operation. Record order, active/inactive records,
all semantic dataclass fields and store metadata are bound. Direct bypass mutations are caught by independent
whole-store verification before checkpoint admission. Restoring a snapshot rebuilds the index.

Durability: before any phase in a batch runs, a new intent is fsynced, including its directory chain. Outcomes,
returned costs and ledger deltas are retained separately in hash-chained batch files, with fsynced receipts.
Caught exceptions close their charged journal and leave failed-attempt evidence. An unclosed intent, truncated
batch, missing receipt, unexpected filename, broken chain or prefix gap **refuses automatic resume**; unknown
crash work is not assigned an invented zero cost. Independent reconciliation would be required to resume such a
hard-killed attempt. This is the permitted refusal branch of the task, not full recovery of lost process counters.

Checkpoints retain full immutable/base identity checks, full legacy scientific-state hashes, independent
record-index verification, durable snapshot/report/receipt bindings, and verified import equality. Other endpoint
queries retain the old clone/restore behavior. The fast path is limited to ordinary edit/immediate phases.
result.json includes per-phase-kind count/errors/wall_seconds/operation_seconds and prior-attempt timer summaries.
Read those timers for re-profiling; do not infer operation time from file mtimes.

Done-when check: a two-edit TinyBase cell covers retention/locality/unseen/drift/challenge endpoints, interrupts
incremental mode during the second checkpoint, retains checkpoint 1, resumes in a new attempt, and reproduces
scientific checkpoint content and state. Each profile's receipt hashes validate independently. Receipt bytes
