## Usage

Feed the installed-analysis snapshot and a stable D11/daily-D13 snapshot for the same matrix. The receipt root is explicit because scientific analysis does not declare that operational identity. From the repo, under the standard CPU environment:

    ../venv/bin/python -m scripts.r1_d14_report \
      --analysis PATH_TO_ANALYSIS_JSON \
      --output logs/NEW_REPORT_DIRECTORY \
      --watch-journal PATH_TO_STABLE_WATCH_JOURNAL \
      --accounting-report PATH_TO_D11_REPORT_OR_D13_DAILY_JSON \
      --accounting-receipt-root PATH_TO_MATCHING_QUEUE_RECEIPT_ROOT

Omit both accounting arguments to report unavailability. A stale snapshot is refused; obtain a coherent new one. D13 boundary cost-proposal files are not daily-D13 inputs; supply their separately produced D11 report. No formatter action dispatches cells, signs or sends notifications.

Reproduce with python -m scripts.r1_d14b_rehearsal --name rehearsal-NEWNAME using the CPU venv. This uses existing round 39 synthetic resources and substitutes the reduced validation contract only inside that isolated process.
