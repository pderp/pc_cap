| R23-01 means vs summed gradients | **answered** | The optimized objective is the SUM over prefixes of the per-prefix terms (that is what the gate-5 finite-difference test checks); the logged `answer`/`preserve` values are per-prefix means for readability. `docs/revision_v1_losses.md` now states the objective as the sum; no code change. |
| R23-02 support answers absent from zero-step codes | **repaired (the important one)** | The record key still comes from the support PROMPT observation, but the initial code now comes from the prompt + answer observation with the answer span as the summary mask (`adapt.py`, `train.featurize`/`_records`). Test: swapping the taught answer changes the code and leaves the key unchanged. `LossConfig(fast_steps != 0)` is rejected rather than ignored; the differentiable fixed-unroll reference remains unimplemented and is named as such. The pilots run before this repair (`bp_*`, `cf_*`, `epc_*`) are kept as "prompt-only-code" history in `docs/R1_stage2_notes.md`. |
| R23-03 "alternating ePC" updates cap weights only | **answered** | Correct: the base is frozen by design in Stage 2 (plan 9: the base is fixed during editing evaluation). The condition is renamed "ePC-credit surrogate for the cap weights" in the notes and loss table; matched base-update phases are not a Stage 2 claim. |
| R23-04 rejected revision retires the old record | **repaired in part / answered** | A non-finite fast update now removes the new record and reactivates the superseded one (`RecordStore.remove`, test). A revision whose fast steps merely do not improve the loss keeps the new record with its answer-derived initial code — the support example is the authority on the fact, and the accepted-step rule governs only the code step. That reading is recorded here; if the lead prefers full rollback on no-improvement, it is a one-line change. |
| R23-05 prefix-related queries share selection | **answered, boundary documented** | The selection cache keys on the longest cached prompt that prefixes the query; the v0 evaluator sends a query's prompt first and its teacher-forced extensions afterwards, which is what the rule is for. Two independent queries where one prompt is a strict prefix of the other would share a selection; on the development sets no such pair exists (checked in the pilot data), and `reset_queries()` is the explicit boundary. An explicit `begin_query` API is noted for the harness adapter. |
| R23-06 snapshot omits semantic config | **repaired** | The snapshot carries the full semantic configuration (reader/controller/fast/null threshold/single-site/cached-pass/base hash/encoder version) and `import_state` refuses a mismatch (test). |
| R23-07 ceiling omits weights | **repaired** | Reusable-weight bytes are counted in the store's byte report and against the same ceiling; metadata stays at the declared 128 B/record and the flat index at 0 B (both are what the implementation uses). |
| R23-08 returned costs / ledger | **acknowledged, open** | The base charges every call to the ledger; the learner's returned `RevisionCost` counts the calls it makes. A synchronized reconciliation (returned vs ledger delta per phase) is added to the gate-6 checklist for the next profile run rather than claimed now. |
| R23-09 ePC ignores the code penalty | **repaired** | `EPCTrainer` refuses `w_code_norm != 0`. |
| R23-10 training geometry vs L2 top-k | **repaired** | `RecordStore` retrieves by the reader's dot-product score (descending, deterministic ties), the same score the applicability softmax trains with; the L2 metric is kept only for diagnostics. Deployed candidate recall against the training population is to be measured in the next stream evaluation. |
