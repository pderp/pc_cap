## Sampling policy and limitation

Source: `docs/ongoing3.md` Lane F, `docs/ongoing2.md` Lane F, PDF Baselines/S2. `ReplayLearner(lora_learner, seed=0, ceiling_items_fraction=0.05, ceiling_bytes=None)` uses the base's `B_cap` when no byte ceiling is supplied.

Capacity is `min(floor(fraction * seen), floor(ceiling_bytes / slot_bytes))`, calculated with an exact rational fraction. When capacity grows, the current completed item fills a new slot. Otherwise draw `j` uniformly from `[0, seen)` and replace slot `j` only when it is occupied. This is a **growing-capacity adaptation of Algorithm R**, not an exactly uniform sample of all historical edits. Floor rounding admits no item among the first 19; item 20 first occupies a slot; filling additional capacity also favors the item present at that growth boundary. Exact all-history uniformity cannot be recovered without retaining discarded historical examples beyond the storage rule.

An optional clarification was presented to the user about this ambiguity. No answer had arrived after the response interval, so the implementation proceeded with the explicitly stated growing-capacity interpretation. This is an implementation assumption, **not a user-approved scientific amendment**. The policy string `growing_capacity_algorithm_r_not_uniform_all_history` is embedded in every snapshot and outcome. The orchestrator should review this sampling interpretation before any scientific B3 comparison or freeze; the uniformity test below applies only to the fixed-capacity special case.

## Behavior and accounting

- Each of the LoRA learner's optimizer steps samples one existing reservoir item uniformly when any are present, and trains on the new item plus that replay item in one Adam step. Loss is the equal mean of the two per-item mean answer-token losses.
- The current edit is admitted only after all its optimizer steps complete; it cannot replay itself during its first update. The empty-buffer path is exactly a LoRA step on the new item alone. Stream order, not item identity, defines past exposure; a repeated input later in the stream is a new exposure.
- Every new/replay sequence charges one full forward, one reverse, and its unpadded teacher-forced input tokens. Sampled slot and replay input-token count are returned with each step; final admission action/reason is also recorded. Read-only predictions delegate to LoRA and leave reservoir/RNG state unchanged.
- Slots contain two int32 length fields and padded prompt/answer token IDs only. Each slot reserves `n_pos + 3` int32 words: **4,108 bytes** for GPT-2's 1,024-position context. Fixed-width storage avoids extra short-item admission preference from variable byte sizes, at the cost of counting unused padding against the buffer ceiling. Stored payloads never exceed the requested byte ceiling or the floor-rounded item limit.
- Snapshots contain all LoRA adapters/Adam state, token buffer and length fields, seen count, fraction/ceiling/policy/configuration, and NumPy PCG64 RNG state. Import validates the buffer and a candidate RNG before importing the inner learner, and refuses malformed or over-capacity state. Existing `ItemGuard` restores both learners and RNG after a stopped item while preserving incurred ledger cost.
- Persistent memory reports count all adapter arrays, Adam moments/count, padded buffer payloads and exact serialized metadata/RNG overhead. Frozen base weights and transient activations are excluded from this editable-state representation. The buffer ceiling constrains the stored slots, while `allocated_bytes` reports the full baseline state including optimizer and metadata; it is not silently clipped to `B_cap`. `per_bank[0]` exposes buffer bytes, item count, capacity, slot size and policy.
