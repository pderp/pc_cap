The monitor command policy omits recipe argv. Attribution therefore uses audited
driver/wrapper entry points, boot ID, PID and start ticks, plus attempt windows
inferred from result/phase mtimes and recorded durations. The legacy CounterFact
result lacks an attempt duration; its first completed phase mtime minus its
phase duration supplies the start estimate. Concurrent candidate processes,
insufficient coverage or gaps above 30 s cause refusal, not arbitrary selection.
These are temporal matches, not proof from an embedded recipe/PID receipt.

Monitor values are maximum sampled RSS. They can miss a transient peak; kernel
high-water RSS is also retained separately. GNU time's kernel maximum RSS is
directly tied to the exact successful recipe path/hash and execution command.
Historical source matching is not a guarantee that future concurrent runs have
the same memory envelope. Ceilings remain measured value × 1.5, applied once.

Live monitor files are read to a bounded prefix. Torn last lines are excluded.
Filtered excerpts preserve process identity, timestamps, sample offsets/hashes
and complete-prefix hashes without copying the entire 1.2 GB monitor store. These
excerpts survive the 48-hour raw-log retention; hashes identify the bytes read,
not later appended segments. Monitoring services were neither edited nor restarted.
