2026-09-28, Capex. **CPU implementation and native stream smoke complete; GPU runs remain Capstan's.** Built against the applied PC-9/10 runner without editing its live files. charlie selected **additional acquisition updates** for the compute control; repeating gradients at unchanged writes is not this experiment.

## Treatments

`aw/pc_random_credit.py` implements **SE-R**. Each credit call computes the actual corrected eight-step error signal, then independently randomizes orientation at each site using an isotropic Gaussian draw scaled to that signal's norm. Zero signal stays zero. The installed transport normalizes direction afterward. Real nine-forward/nine-reverse reference work is paid, and the transactional learner, threshold, per-round A and R remain unchanged. PCG64 uses a separate seeded stream, serialized with the cap; eviction RNG is unaffected. Snapshot continuation reproduces future draws.

`aw/pc_matched_credit.py` implements **SE-AM**. The same item in the completed eight-step SE-E stream supplies its **offered learning-operation allowance**: full forwards + partial forwards + reverses, each counted once. The unchanged adjoint search may spend that allowance on additional transactional acquisition rounds, keeping the same per-round A and threshold. Gold-prefix order is retained; earlier prefixes may consume the remaining item allowance. A next base call that would exceed it is refused. An unfinished round is rolled back, but all actual compute remains charged. Earlier completed rounds survive. Threshold attainment stops useful work, leaving unused allowance explicitly recorded. This is equal offered operation budget, **not necessarily equal realized compute, FLOPs, time or writes**. No wasteful padding is introduced to force equality.

Both behaviors answer the approved control questions. A tiny actual SE-E-reference test matches the operation count within one base call; another demonstrates multiple completed useful adjoint rounds. The deliberately small native smoke budget sometimes funds only another partial search, which rolls back; it is not evidence of an extra successful write on every item.

## Drivers, scope and reports

- `aw/pc_random_run.py`, `aw/pc_matched_run.py`: private bindings of the **current** native cell/stream engine. Every config and finish records the control treatment. The matched driver verifies exact reference source archive, item order, completion, eight-step cost relationship and fresh calibration state.
- Each driver has the established **12-cell paired scope**: two datasets × three realizations × one order × (ordinary SE-A + the new arm). Thus both runs together are 24 cells, including newly repeated SE-A baselines. They do not pool or silently relabel the 60-cell historical experiment.
- Each profile has four development cells, ten items each. Matched profiling uses the already completed ten-item SE-E development reference. Real exposed runs retain all 1,000 zsRE / 300 CounterFact items.
- `aw/pc_control_report.py`: strict treatment/source/pairing validation, six realization-level pairs, efficacy and bounded-text secondary scores, actual costs, offered/used allowance, threshold stops and partial-round rollbacks. It does not infer ordinary-text harm from efficacy.
- `aw/pc_controls_smoke.py`: actual tiny native stream, query, snapshot and ledger paths. Saved output: `results/additional_work/PC12/cpu-smoke-20260928/`; snapshots under the corresponding assets directory. This is synthetic validation, not a research result.
