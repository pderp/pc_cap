Procedure, matching v0 S2-01:
1. Construct the bound original BP base with cap disabled.
2. At the last position of each edit, paraphrase and outside prompt, extract the three registered bank-site residual vectors and compute the installed z(h) feature.
3. For each bank, compute Euclidean distance from each paraphrase key to its owner edit key, and each outside key to the nearest of all 100 edit keys.
4. Form the existing 20-quantile distance grid (quantiles .05,.10,…,1). Select the largest positive radius with empirical outside false-fire ≤1%, breaking radius ties by coverage. The unmodified calibrate_radii function supplies every candidate.
5. If no positive radius qualifies, emit zero radius and the exact-key limitation. Separately calculate zero-radius false fires: an exact-key collision can mean even that fallback fails the empirical criterion.
6. Save finite key arrays/ownership under assets; emit all candidates, chosen counts/denominators, coverage, fallback status, source/base/array hashes, lease and ledger into a new pc_cap/results/R1 directory.

With 500 outside prompts, at most five hits meet the point-estimate criterion. Searching the grid on that population is not a certified 1% population bound. No optimization, edit writes, live key motion, reader training or temporal displacement simulation occurs in this static v0 calibration.
