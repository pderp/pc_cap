## Implemented components

- `RecordDigestIndex`: ordered hash of full MemoryRecord field hashes plus caller-supplied state metadata.
  Rehashes only explicitly changed leaves; automatically tracks deletions/order in the supplied complete inventory.
  New records require a mutation event. Full independent leaf recomputation detects an omitted mutation at a
  checkpoint. Rebuild/verify after restore. It is a versioned `record-digest-v1` root, not a replacement encoding
  for the legacy LearnerState SHA.
- `PhaseJournal`: one immutable file per N edits (default 16), individual edit/immediate records inside,
  file SHA chain, explicit tail flush before checkpoint, receipt binding and path/order/hash verification.
  Keeps caught failures/cost records; never appends to an existing file or restarts inside a partial batch.
- `read_only_immediate(..., integrity_profile="incremental")`: exact RevisionCap only; same CellAssays.item
  call, skips clone/import on success, resets ephemeral query cache, retains full state and immutable identity
  checks on both sides. Unknown learner families refuse, and the full profile retains clone/restore.
- `verified_checkpoint`: full legacy content hash, serialization, independent restore and post-import equality.
  Returns bytes to the caller for an immutable assets snapshot; does not write resources inside pc_cap.

## Why an automatic production switch is not yet warranted

The task asks for a cheaper equivalent. The new components are useful, but a generic cache of `state_hash()`
or `identity()` cannot establish equivalence. RecordStore.lexical_version changes on add/remove, **not on code or
delta writes**. Queries populate ephemeral caches; unsupported v0 families have other persistent state. Caching
file checks by timestamps or base checks by object identity would miss changes the current driver rejects.

The new module therefore leaves full immutable checks in place and does not claim to eliminate the dominant
fixed base-checksum work. Immediate queries still use full state hashes until the mutation-index integration is
audited. Incremental mode aborts on unexpected read mutation; the caller must restore the last complete checkpoint,
retain the failed attempt's charged cost and resume the verified prefix. It does not promise the old pre-phase
rollback state after an exception. Successful checkpoint scientific state/results must remain equal.

Batched logs also change crash granularity: SIGKILL can lose up to N unflushed, unreceipted edits. Failed-attempt
resource spend must be preserved by an independent durable meter or a conservative reservation reconciliation.
Without that binding, batched logs alone do **not** preserve the old per-phase accounting granularity.

   edits-per-file into the manifest/code/adapter identity; refuse unknown flags or unsupported learner families.
   Retain all current payload/role/token/source/code/base refusals before model work.
2. Wrap every mutation path: add, supersede (old and new id), rollback/remove/reactivation, set_code, set_delta
   and rebuild_keys. Include store metadata, active/inactive records, source/delta arrays, config and reusable
   weight identity. Do not use lexical_version as a full-state dirty bit. Default full profile for uninstrumented
   classes. Test unreported direct mutations and forbid/check them before admitting a checkpoint.
3. For each edit, collect the original ledger deltas/events/outcome and immediate record, then journal them once.
   Avoid duplicate summation of returned counters and shared ledger costs. Flush caught failures; implement durable
   failed-attempt accounting for process death. Bound the journal receipt from the checkpoint receipt.
4. At each checkpoint retain the existing complete assays, full legacy state SHA and immutable identity checks;
   compare incremental root with independently rehashed records, serialize and verify restore equality.
   A failed comparison writes no successful checkpoint receipt.
5. Resume from the existing unique contiguous receipt prefix; verify report/snapshot/journal hashes and paths,
   restore full state, rebuild the leaf index, and start a new attempt directory. Never append old logs or trust
   an unreceipted tail.
6. Run TinyBase **whole-driver** full/incremental pairs for all endpoints, revision and composition clone paths,
   100/300/1,000 schedule, behavioral misses, checkpoint resume, update/query failure, tampered journal/snapshot,
   source/code/parameter drift and budget failures. The current component parity test does not replace this.
7. Owner re-profiles the exact final reader on the real base. Separate input verification, identity hash,
   clone/export/restore, model execution, serialization and total wall. Only then fill budget/profile fields.
