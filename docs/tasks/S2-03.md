## Implementation and interfaces

- `LoRALearner(base, rank=8, lr=1e-4, steps=10, seed=0)` exposes `update_item`, `predict`, `trainable_tensors`, `export_state`, `import_state`, `state_hash`, `memory_bytes`, and `base_checksum`. For replay it also exposes validated `prepare_item`/`prepare_tokens` and a single-step `train_step` accepting one new item and at most one replay item.
- New `baselines/lora_forward.py` builds each block's fused projection as frozen `c_attn.w` plus Q/zero-K/V deltas. Factors use the stored HF `[input, output]` layout: `B[input, rank] @ A[rank, output]`. Effective scale is 1 (alpha = rank). A is seeded N(0, 0.02), B starts at zero. There is no dropout or weight decay. The JIT differentiates only the adapter argument and uses existing GPT-2 block, embedding, and head primitives.
- Whole-answer training uses `prompt + answer[:-1]` as the input and masks CE onto exactly the answer prediction positions, including the supplied terminating newline. The loss is mean answer-token CE. With replay it averages the two per-item means equally. Each complete edit performs exactly `steps` Adam updates; the external harness controls task epochs and stream order.
- Every training step charges one full forward/reverse per input sequence and all unpadded input tokens. Prediction charges the query column. A nonfinite candidate raises before replacing the live state; the external ledger retains incurred cost. Mid-item rollback uses the existing `ItemGuard`.
- Prediction is an ndarray of `[T, V]` logits with a `.logits` view so both the task's array interface and the existing generic harness work. No harness edits are needed for these imports or calls.
- Snapshots include every A/B tensor, both Adam moments, Adam count, update/item counters, seed/configuration, and frozen base checksum. Import validates inventory, shape, dtype, finiteness, configuration, and Adam count before mutating live state. Optimizer moments and all future-behavior-affecting state restore exactly; the ledger remains external.
- `B0` preserves learner state on every update, returns an accepted no-op with zero update cost, and charges base evaluation through the query ledger. Its snapshot contains only identity metadata.
- Memory reports count actual adapter and optimizer array bytes plus exact serialized metadata bytes; frozen base weights are excluded from editable state. `ceiling_bytes` reports the same `B_cap`; B1 does not silently enforce it as an adapter limit. Python allocator overhead and transient training activations are outside this persistent-state count; peak device memory is separately recorded by the ledger.
