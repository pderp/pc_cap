3. **X15-03 — ambiguous ceiling factor.** The execution plan defines a serial ceiling as
   `1.5 × measured solo cost` and a concurrent ceiling as `1.5 × 1.1 × measured solo cost`.
   Queue code instead multiplies the matrix's bound `wall_seconds` by **1.65** for workers=2;
   serial mode uses that field unchanged. If the matrix stores an already padded serial ceiling,
   the effective concurrency ceiling becomes **2.475 × measured cost**. Decide and bind one
   meaning for that field, then test one concrete populated cell before cost admission. Do not
   fill final ceilings from prose until this is reconciled. No current final ceiling is populated,
   so this is a pre-launch ambiguity, not a measured overrun.

4. **X15-04 — slowdown claim too strong.** The execution plan says per-cell slowdown ≤1.10.
   Independent saved-attempt ratios are **1.1114** (random reader), **1.1335** (ungated learned),
   **1.10036** (v0-stable) and **1.08795** (matched-update). All four final state hashes match
   their solo counterpart. The learned pair spans historical driver versions; these ratios are
   descriptive and exclude initialization. This supports useful concurrency, not a universal
   1.10 upper bound across MQuAKE, CounterFact, S1 or full endpoints. The separate 1.5 safety
   allowance is not evidence for the claimed measured bound.

5. **X15-05 — failure-policy mismatch.** The execution plan promises “fails twice … queue moves on.”
   Both serial and two-worker implementations stop dispatch at the first failed process; workers=2
   drains the other process. Resume/reconciliation is manual. DEC-052 requires honest incomplete
   inventory, not an automatic two-retry scheduler. Correct the plan to describe the implemented
   stop/review/resume behavior, or separately specify/test/admit a retry/skip change before launch.
