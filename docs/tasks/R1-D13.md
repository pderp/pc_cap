After publication, use the exact final matrix, persistent receipt root and watch journal used by the signed launch. For the first report omit `--previous-run`; thereafter pass the preceding generated `daily.json`:

```bash

  --workers 2 --output-dir logs/R1/operations/NEW_MORNING
```

Add `--previous-run logs/R1/operations/PREVIOUS_MORNING/daily.json` for the next morning. The saved D11 report is unchanged; the D13 text explicitly calls its watch cursor **since the previous generated daily report**, not delivered or acknowledged. The orchestrator posts `lead-queue.txt`, checks new global entries as well as this matrix's entries, and promptly relays creep alerts. Generation is never a delivery acknowledgment. Keep the last actually posted D11 reference separately for block reporting. The watch is descriptive under DEC-064, not a cap admission veto.

The report includes artifact-complete and incomplete cells, completed blocks, failed/exhausted attempts, known process-hours, active-ceiling projection and accounting gaps. Unknown live/interrupted process time stays unknown and suppresses projection; no zero cost or elapsed-time forecast is invented. Process envelopes replace covered driver times; overlapping workers and failures each count once.

Health comes from bounded tails of the existing process-memory JSONL and sysmon logs. Read at most two memory segments (2 MiB of complete-line tail each), two sysmon segments (1 MiB each), and memory headers. Byte offsets and raw-line hashes identify selected samples even when a live log grows. A very large record outside that tail can be unavailable; the script does not silently expand to read hours of logs. Partial tails, malformed data, missing samples, older boots, future timestamps and samples older than 120 seconds are disclosed. Memory is compared with the 6,144 MiB launch floor. Top RSS identifies PID **and start ticks**, without guessing commands from reused PIDs. GPU utilization, memory, temperature, power, throttle bitmask and kernel clues are saved observations, not a diagnosis; sysmon has no boot identity and uses local America/New_York time. A fresh low-load sample is not launch clearance.

The current signed operator launch runs the whole matrix and does not automatically pause after a block. ## Crash-resume checklist

1. **Identify the incident and preserve evidence.** Record the boot ID, wall time/timezone, interrupted queue/cell IDs, journal and process-receipt paths. Copy relevant monitor segments and service/kernel diagnostics into a new incident directory under `logs` before the 48-hour retention window removes them. Resource checkpoints remain under `assets`; do not move or rewrite their bound bytes. A recent sample does not establish what happened during the crash.
2. **Establish exclusive ownership.** Verify no old queue or worker is still running, account for PID reuse with boot/start identity, and inspect the queue lock and externally held GPU lease. Do not unlink locks or forge lease state. Reacquire the normal owner lease after a reboot using the established run procedure.
3. **Check immutable admission.** Verify the published freeze, exact matrix and queue bindings, signed cost/protocol receipts, code/environment/backend identities and October 9 deadline. Use the existing queue/backend validators; do not edit frozen source, recipes or ceilings to make them pass. Compare against the authorized launch request and preserve its receipt root.
4. **Reconcile uncertain process time.** Every `start.json` needs its matching finish/cost evidence. An interrupted envelope has unknown cost and blocks automatic resume. Preserve failed attempts and overlap; never manufacture a successful finish or enter zero for missing time. A host/OOM/lease failure stops the queue and requires owner reconciliation; the one retry policy applies to ordinary cell failures. After the second cell failure retain the cell as incomplete.
5. **Verify resumable artifacts.** Invoke normal queue validation of checkpoint SHA/location, unique contiguous checkpoint prefix, exact cell identity, saved state and incremental phase journals. A torn/open phase intent is not automatically repaired. Completed artifacts, not exit status alone, determine completion. Restart only from the last verified durable checkpoint, with prior attempts retained and charged.
6. **Reconcile the watch.** Verify the full journal and append-only prefix against the last report; preserve deduplication. Ensure each artifact-complete cell has its required full-validation watch observation. Do not erase benchmark breaches, recreate observations from guessed values or mark a notification delivered merely because a report was generated.
7. **Check live resources before executing.** Confirm monitor service recovery, current MemAvailable ≥6,144 MiB, disk space, device availability and the live lease. Saved daily health does not replace the scheduler guard. Respect two workers, admitted per-cell limits, shared 750 process-hours and the October 9 stop. Investigate memory pressure before retrying a host failure.
8. **Use the correct execution interface.** The queue command is `python -m scripts.r1_77_queue run --execute` with the exact reviewed matrix/bindings, `--workers 2`, `--min-memory-mib 6144`, `--ceiling-hours 750` and the preserved `--receipt-root`. **The queue has no `--resume` CLI flag**: it detects existing cell output and runs `verify_resume` before passing `--resume` to the correct cell backend. `scripts.r1_77b_sealed_backend --execute --resume` is the individual sealed-cell interface; bypassing queue orchestration is not the normal recovery procedure. The development comparator has a separate `run --execute --resume` interface. Do not copy a development command into confirmation or add a nonexistent queue flag. GPU execution uses the normal CUDA/JAX runtime, not the CPU environment variables in these reporting examples.
9. **Record and inspect the resumed attempt.** Save the owner reconciliation and authorized command in a new incident record. Confirm a new process envelope, verified restore and correct watch behavior. Re-run daily reporting; reprice only once the global queue is idle. If any verification fails, preserve evidence and stop; an unsigned D13/D12 report cannot authorize a workaround.

Validation: synthetic queue tests exercise generation-based watch deltas, breach/creep alerts, unknown costs, consistent publication, D11→D12 composition and refusal on a later live worker. Saved-monitor fixtures cover units, timezone, line hashes, partial tails, stale/future/previous-boot samples, low memory and unavailable GPU data. No real queue has been launched or resumed by this lane.
