## Scientific and storage contract

`full_validation` is an explicit recipe object binding the ordinary-text inventory, token-file SHA-256, source length, complete-window bytes, tail/context/checkpoint policy, references and denominator. Production requires exactly 1,931 complete 128-token windows, 245,237 prediction positions and 121 dropped trailing tokens. No test split, repetition or incomplete tail window is added. The sampled drift definition must equal the first 128 source windows.

For every scored prefix, the endpoint recomputes selection with the audited RevisionCap or v0-family batch reader. S1 compares cap-on with its continued cap-off base and separately with the original base. All nine conditions are covered by the CPU tests. KL means **KL(reference || cap)**. Tiny negative KL roundoff within 1e-10 is clipped to zero; larger negatives and nonfinite values fail the assay.

The compressed NPZ has a float64 array `values` with shape `(1931, 127, 5)`. Fields, in order, are `loss_cap`, `loss_capoff`, `loss_original`, `kl_capoff_to_cap`, `kl_original_to_cap`. Row `(w, p-1)` corresponds to `w{w}:p{p}`. Uncompressed storage is 9,809,480 bytes per final endpoint, about 9.36 MiB; actual compression is measured, not assumed. This is about 3.53 GB before compression for 360 completed cells, excluding retries and other logs.

Only the scalar output array, source tokens and aggregate work counters persist across batches. Hidden states, logits and per-prefix selection records remain bounded by the physical batch; no list of 245,237 hidden states or prefix copies is built. Batch padding is charged. The report includes full coverage, state/checkpoint/manifest/source/reference hashes, strict exceedance counts at .01/.1/1 nat, signed and positive maxima, and HT-1's fractional empirical ES95 of positive harm. Full-population summaries are separate from sampled talk statistics.

At the final checkpoint, an overlap gate compares all sampled losses against the matching full-population positions (maximum absolute difference ≤1e-3 nat) and requires identical loss-difference exceedance counts against **both** references. CPU parity is validated; the owner runs will provide the real-base gate. These are comparisons at the same checkpoint, not comparisons between different training states.

## Integration and integrity

The patch adds the new module to the driver identity. With a bound `full_validation` contract, it runs the existing sampled implementation at **every** declared checkpoint and the additional full assay at the final checkpoint. Inspection showed the old execution loops ran the sample only at the final checkpoint; this is an actual cadence addition and needs cost accounting. Historical recipes without the field retain their old behavior and are not DEC-063 production recipes.

Both loops keep their existing identity/state checks, journaling, snapshots and receipt chain. The incremental profile borrows read-only state for the full phase, as it does for sampled drift; the full profile retains defensive clone/restore. NPZ bytes are flushed and fsynced, then their hash is bound through the checkpoint report and final receipt. Resume verifies that the NPZ still exists in the report's attempt directory, has the expected hash/shape/type, and is finite. Failed assays cannot produce a completed checkpoint receipt.

The sealed fork receives the same hooks and its donor pin is updated to the **reviewed proposed driver hash**, not merely to whatever happens to be installed. This patch does not create a frozen manifest or admit production. Its historical optional-field compatibility is not a substitute for requiring DEC-063 in new production recipes and admission/analysis; those follow-ups are listed in R1-58k.

Costs: `full_validation:<checkpoint>` is a separate outer phase. Its endpoint records operation wall time including verification/reductions/durable vector output. Use the outer phase timer when budgeting integrity and serialization overhead. JAX memory records use the allocator's process-lifetime peak, clearly labelled; CPU or unavailable telemetry is `null`, never zero. Linux host RSS is also a process-lifetime high-water mark. Neither is presented as an isolated phase allocation peak. Preserve `/usr/bin/time -v` and the external monitor during owner execution.
